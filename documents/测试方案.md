**状态：测试规划档案。** 当前已执行的自动化测试、未执行的真机与性能项分开记录，结果以《测试记录.md》为准；本文用例表不自动代表每项已通过。后续测试代码统一放入项目根目录 `tests/`；本阶段不创建测试代码。

## 1. 测试目标与边界

验证桌面与 Android 上的任务、日期视图、公历/农历重复、A/B 模式、模板、固定任务时区、原生提醒、同步收敛与数据保护。iOS 仅在分发和设备条件满足后做条件兼容验证，不将普通私人插件可安装作为既定能力。

暂缓功能不作为必交付：法定假期/调休、独立子任务、独立系统通知、多重提醒、通用模板库、统计、批量编辑及其他未选扩展。正文复选框不受管理，必须以“不被插件改写”作为负向断言。

需求中的“默认设计”与用户明确决定均需覆盖，但测试报告要记录对应设计版本；技术验证失败不可将既定体验静默缩小为更容易通过的测试。

## 2. 测试分层与独立判据

| 层级 | 主要验证 | 判据与限制 |
| --- | --- | --- |
| 纯领域逻辑 | 视图边界、重复、次数、状态迁移、农历和时区换算 | 固定时钟、显式时区、独立样本；不依赖当前系统日期 |
| 性质与模型测试 | 任意操作序列、重放幂等、预览无副作用 | 简化参考状态机与不变量，不仅照抄实现函数 |
| 适配器集成 | Joplin 数据分页、原生字段、资源引用、元数据、设置 | 可注入延迟/失败的替身，加真实开发配置交叉检查 |
| 插件端到端 | 页面操作到笔记与记录的完整链路、恢复、同步 | 使用隔离配置和测试数据；检查宿主实际数据而非只看页面 |
| 真机与系统 | 桌面系统通知、Android 锁屏/后台、时区、布局 | 记录 OS/Joplin/WebView/权限/省电状态；模拟器不能替代系统交付证据 |
| 性能 | 可见范围预览、索引更新、交互、内存 | 相同版本与种子数据，冷/热分开；指标为待验证建议 |

Joplin 官方建议以独立开发配置测试，避免修改正式数据。移动 Web 构建可安装 `.jpl` 并调试插件，但不能证明 Android 通知或后台行为。[官方开发入门](https://joplinapp.org/help/api/get_started/plugins/)、[移动插件调试](https://joplinapp.org/help/api/references/mobile_plugin_debugging/)

## 3. 必须持续成立的性质

| 编号 | 不变量 |
| --- | --- |
| INV01 | 当期未完成且未跳过，不能产生下次实际周期；浏览、刷新、同步、通知触发本身不构成推进 |
| INV02 | 完成或明确跳过当期只推进一次；同一逻辑周期重试、重复点击、事件重放不重复推进 |
| INV03 | 已推进旧周期撤销再完成不新增后继；不删除、覆盖已有后继的用户内容 |
| INV04 | 预览仅为派生结果，无待办创建、提醒调度、次数消耗或模板写入；关闭重开不产生副作用 |
| INV05 | 同一视图同一逻辑周期只计一次；预览转实际后替换身份，不同时出现两条 |
| INV06 | 模板修改不覆盖已生成笔记；历史不因系列规则或模式修改而改写；正文检查项保持原样 |
| INV07 | 任务时区不随设备显示时区变化而改写；全天日期不经过 UTC 换算后漂移 |
| INV08 | 暂时延期、稍后提醒、原生提醒写回不改变系列锚点；内部写回不触发无限循环 |
| INV09 | 跳过占一次、撤销再完成不重复占次；到达截止日期/次数后不再生成或显示越界周期 |
| INV10 | 双端离线操作后可检测重复或冲突，最终只保留一个可操作的逻辑后继；不得丢失被用户编辑的副本内容 |
| INV11 | 重试与恢复不复活已删除任务；移入回收站与恢复均尊重用户实际动作 |
| INV12 | 停用后原始笔记仍可访问；单纯启用、升级或恢复同步不批量生成遗漏任务 |

INV10 要同时报告“曾产生的物理笔记数、逻辑周期数、收敛后可操作数、内容保全情况”。仅界面隐藏重复笔记不算达到无重复；离线下不能用本地互斥锁证明跨设备唯一性。若架构只能最终收敛而无法避免短暂物理重复，须明确限制并进入设计评审，不能把它写成全时刻强一致已满足。

## 5. 并发、乱序与故障注入

采用至少两个隔离的 Joplin 配置或设备，连接专用测试同步目标。A/B 两种笔记模式分别执行；每次记录系列ID、周期逻辑键、规则版本、操作ID、原生笔记ID、模板版本及用户修改摘要（字段名待设计确定）。

| 编号 | 故障/交错 | 观察点与预期 |
| --- | --- | --- |
| C01 | 两端离线同时完成同一周期，按 A→B、B→A 顺序同步 | 检查物理重复、逻辑唯一、内容保全和最终收敛；再同步不继续生成 |
| C02 | 一端完成另一端跳过；一端撤销另一端完成 | 终态有确定可解释的冲突处理，推进只一次，不重复消耗次数 |
| C03 | 一端改规则/模板/模式，另一端完成旧版本周期 | 版本语义明确，历史不改；不得静默用不完整混合配置生成 |
| C04 | 一端删除/移回收站，另一端推进 | 不擅自复活删除项；可恢复记录和明确冲突提示 |
| C05 | 旧周期撤销后，两端分别补完成与编辑后继 | 不删除后继，不因旧记录再次生成；用户编辑可恢复 |
| C06 | 同一事件重复投递、倒序到达、延迟一部分元数据 | 幂等、缺失状态明确，不将暂缺认作新任务；最终结果不依赖重试次数 |
| C07 | 在“记操作/写当前笔记/建后继/写关联/改提醒”各持久化边界中断 | 重启可识别未完成操作，重试不重建或丢笔记；逐边界验证，不假定事务覆盖多笔记 |
| C08 | API分页第二页失败、写入超时但实际成功、资源暂缺 | 不误删未读任务；超时后查证/重试安全；缺附件不静默丢引用 |
| C09 | 同步中模板附件被删除、旧数据版本、损坏元数据 | 隔离问题并提示，不破坏其他系列；升级失败可恢复 |
| C10 | 控制笔记、不可变operation键分批/乱序到达，原始user_data不可枚举或不完整 | 缺父操作、规则或模板时暂停有副作用投影；不能提前清空原生提醒/日期/完成状态；版本能力门禁与诊断明确 |
| C11 | 两端时钟相差数小时/数天，操作ID到达乱序，系统时钟回拨 | 不按墙钟胜负裁决因果顺序；同一操作身份稳定；并发分支保留而非静默丢弃 |
| C12 | 原生值检查后、写入前被用户修改；写成功后receipt未落地 | 检查+写+读回不是原子CAS；保留修改证据并按设计暂停或冲突恢复，不宣称读回能防全部覆盖 |
| C13 | A模式复用笔记后，旧完成事件/同步快照再次到达 | 旧状态绑定原周期，不当成当前周期新完成，不连续误推进 |
| C14 | 模板独享附件、仅模板引用的附件经历宿主资源清理及同步 | 资源引用实际可保活；编辑模板、生成新周期、离线恢复后附件仍可读取，不能只比较ID |
| C15 | receipt/绑定/推进操作分开到达另一设备；A旧完成回声、B插件跳过转普通笔记回声 | 可跨端追溯所属周期和写入来源；不把A旧完成当新完成，不把B内部跳过误认用户脱管；证据不足时暂停投影 |
| C16 | 同系列预览多期后延期跨期再完成，或修改规则使多个预计日期重合 | 预计位置身份与真实父链周期身份分离；按规则版本/计划位置替换，不用同一个next ID覆盖全部预览，不按日期误合并不同周期 |

每个交错执行后至少再做一次完整同步、一次插件重启、一次相同操作重放，核对 INV01—INV12。不能用“调用返回成功”代替宿主数据落地检查。控制笔记下 `op:<opId>` 不可变键、周期ID、规则DAG、receipt等是架构候选，最终按设计规范版本固定测试协议；单键日志也须证明枚举、完整性和冲突恢复能力，不因命名为不可变就视为已成立。缺父操作、缺模板或来源不明的投影必须测试整个相关系列停止副作用，不能只缓冲问题操作后继续用残缺快照清提醒或改待办类型。

## 6. 原生提醒真机矩阵

原生提醒只是一条宿主提醒字段。插件的任务日期、系列锚点、延期和稍后提醒必须按设计分离测试，不把保存 `todo_due` 等同于系统必达。官方说明桌面与移动都支持待办通知，展示及桌面依赖由系统决定。[Joplin 官方通知说明](https://joplinapp.org/help/apps/notifications/)

| 编号 | 操作/状态 | 记录与断言 |
| --- | --- | --- |
| N01 | 新建定时/全天、无提醒、显式开提醒 | 期望时刻、字段值、系统通知实到时刻；全天不无提示设午夜提醒 |
| N02 | 提前/延后提醒、插件内稍后、取消提醒 | 旧时刻不再误触发，新时刻调度一次；任务锚点不变 |
| N03 | 完成、跳过、删除、下一周期生成 | 当前提醒清理，后继仅在推进后调度，不为只读预览调度 |
| N04 | 插件写字段与原生界面改字段交错 | 无递归写回；来源与状态可解释，不把稍后当系列改期 |
| N05 | 桌面前台、最小化、托盘、完全退出；Android前台、后台、锁屏 | 区分“插件运行”和“宿主已预排通知”；退出态不作未经验证保证 |
| N06 | 通知拒绝/恢复、勿扰、省电、进程终止、设备重启 | 能力边界与提示真实；恢复不补发一串过期周期 |
| N07 | 双端同时启用提醒、单端原生字段修改后同步 | 每设备重复与跨设备各一次分别记录，不把两台各响一次误判单端重复 |
| N08 | 网络断开、系统时钟校正、时区改变 | 绝对时刻与固定任务时区语义一致，实际调度差异可追查 |

桌面至少覆盖实际声明支持的 macOS、Windows、Linux；Android 至少一台真实设备，并尽可能增加另一厂商设备验证电池策略差异。记录提醒设计时间与实到差值、通知ID/可用日志、权限和系统状态。投递容差按实际宿主能力建立，不把桌面退出或 Android 强制停止后的必达作为未声明承诺。

## 7. 农历独立核验

独立判据选择香港天文台公布的公历与农历对照表，而不是用所选农历库的另一个 API 或另一个封装自行证明。官方提供 1901—2100 年表及文字版本；下载时记录来源、取得日期、文件校验值和人工复核人。开发库若本就来自该表，要说明数据来源相同，另以算法性质和重点人工核验补充，而不宣称完全独立。

来源：[香港天文台对照表](https://www.hko.gov.hk/sc/gts/time/conversion.htm)、[文字版索引](https://www.hko.gov.hk/sc/gts/time/conversion1_text.htm)。官方提示部分远期接近午夜的新月/节气可能产生一日差；发现差异须保留原表、算法版本和日期进行调查，不擅自修正测试期待以匹配实现。

- 目标有效范围逐日比对公历→农历的年、月、日、闰月标志，并检查逆向唯一还原。范围首尾需要先给出实际完整可转换区间，不能仅报“1901—2099”而不测边界日期。
- 单独核验每年春节、除夕、全部闰月前后、大小月边界、农历三十遇小月、普通月年度不额外命中同名闰月。
- 闰月年度重复：有对应闰月命中闰月，无对应闰月回退普通月；摘要显示回退。农历每月将闰月计为独立月。
- 对多次重复生成核验原始农历锚点未被公历日期替换；本次小月回退不导致下次永久使用二十九。
- 农历换算基准固定 Asia/Shanghai，设备显示时区不同不改变农历原规则；超范围/无法转换时明确提示，不产生伪日期或无限重试。

## 8. 时区与夏令时

使用显式 IANA 时区和固定时钟；记录 JS引擎、ICU及可取得的 tzdb 版本信息。系统时区数据会更新，不能只记录 UTC 偏移代替规则版本。[IANA 官方数据库说明](https://www.iana.org/time-zones)

| 编号 | 案例 | 预期 |
| --- | --- | --- |
| Z01 | Shanghai 09:00任务，设备仍Shanghai但人出国 | 不按GPS/IP改变数据、显示或提醒 |
| Z02 | 设备Shanghai→Tokyo→其他时区 | 单次实际时刻不变；显示可换算并注明任务时区；原时区字段不被改写 |
| Z03 | 全天任务设备跨国际日期线 | 保持日历日期，不漂移前后一天；“今日”归类按已定视图语义核对 |
| Z04 | America/New_York每日09:00跨春/秋转换 | 当地09:00不变，不能简单每次加24小时 |
| Z05 | DST缺失02:30与重复01:30 | 缺失/重复钟点按设计唯一策略解析，预览和实际生成一致，仅一条周期 |
| Z06 | Australia/Lord_Howe等非整小时转换，Asia/Kathmandu非整点偏移 | 不能假定所有偏移或夏令时均为整小时 |
| Z07 | 改设备时区与同步、稍后提醒、延期同时发生 | 同一任务身份与锚点稳定，未生成预览不被错误写回 |

DST精确日期从固定版本数据生成并核对，避免把可能变化的政治规则硬编码为永远成立。可用 NIST 当前说明辅助复核美国转换样本，不替代所有时区判据。[NIST 夏令时说明](https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst)

架构师当前候选默认值：缺失钟点按缺口向后平移（如02:30→03:30），重复钟点选更早实际时刻；原始重复钟点不被本次平移永久改写。设计定稿后，Z05须同时断言实际时刻、当地显示和下一正常日期恢复原钟点，不能只测“能返回日期”。

- L档可接受目标需根据真实设备基线再定；即使性能不达，也不得通过无限提前建笔记来替换只读预览设计。
- 调试器、详细日志和性能录制分别标注；正式计时使用发布构建并关闭无关调试。

## 正文双区与 schema3 回归补充（历史方案，已由短pair方案替代）

归档模式首次开启时，首篇的原始正文必须完整保留在执行区，并复制为可原生编辑的模板区；未来任务只使用模板区。测试分别改变执行区与模板区，断言执行日志、勾选状态不污染后继，模板修改只影响尚未生成的周期。持久化业务 userData 不得保存完整模板正文，成功的本机创建恢复记录应清除临时正文；失败记录仍须足以恢复原请求。

解析器覆盖无标记、四标记缺失/重复/乱序、代码围栏中的伪标记、缩进代码、模板内任意长度反引号、区外附加正文及清理可逆性；损坏结构须保留原文并报告，不能按空模板推进。生命周期覆盖 A 无分区、A→B 初始化、B→A 生效后重新锚定、删除旧 B 首篇不影响当前 A、删除当前 A 不复活，以及 B 根缺失保存完成与显式幂等重试。
