# Issue 54 修复与验收记录

## 第二轮：处理 2026-10-30 23:36 验收评论

### 请求记录容量

- 已完成的 `request-saved` 按分片保留最近最多 32 条，16 个分片总计最多 512 条，最长保留 24 小时；内存结果缓存也限制为最多 512 条，并检查有效期。
- 启动时回收存量已完成请求，每次写入时滚动回收。恢复队列接近容量时，已完成的去重回执让位于未完成的恢复工作。
- `request-pending`、未完成创建、日志、移动等恢复记录不纳入上述清理；异常和未完成工作保留。
- 去重是有界窗口：超出保留条数或有效期后，不承诺旧 requestId 继续去重。
- 初次保存请求或保存最终回执失败均返回结构化 `status: error` / `code`，包括 `OUTBOX_CAPACITY`，不再从最终回执写入路径直接 reject。

回归测试连续执行 10000 次不同 requestId 的 savePreferences，全部成功，持久化结果稳定为 512 条；独立运行约 3.51 秒。最近请求重试、重启去重、24 小时过期及启动回收均验证。另将 16 个分片各填满 510 条已完成请求与 2 条未完成记录，启动后已完成记录缩至 512 条，32 条未完成记录及其创建正文完整保留。真正被未完成记录占满时，返回结构化容量错误并保留原记录。

### 标签与性能

全量扫描通过 `tags/:id/notes` 分页反查标签归属，不再逐待办请求 `notes/:id/tags`。单篇增量刷新仍只读取该笔记及其标签。标签 ID 排序后比较，返回顺序变化不导致版本变化。

基准环境：MemoryJoplin，5000 篇笔记，其中 500 篇待办，无标签；分页 100；每篇正文为 1100 字符。初始化后执行一次显式 refresh，统计 data API 调用。

列表扫描不请求正文。模板读取和创建内容校验等场景仍按 ID 读正文。笔记本和标签目录缓存至下次同步完成或手动全量刷新；单篇增量刷新不会立即更新新建的笔记本/标签目录。

### Advance/defer 日志

- 使用固定八层的持久化哈希树保存各因果状态的计划日期，替换随历史增长的 Object.create 原型链。父分支状态保持独立。
- 因果遍历和祖先枚举改用显式栈，避免递归层数随日志长度增长。
- 基准包含完整的 complete → Advance 因果边，然后对历史周期逐一 defer，而非仅测 SetTaskFields。
- 500 个周期（1500 条操作）约 7.73 ms；1000 个周期（3000 条操作）约 15.07 ms。测试核对所有 defer 的旧值、新值及工作量随操作数增长的比例，并验证历史计划日期的分支隔离。
- 逆序输入包含 10000 个周期、30000 条操作的因果链，无调用栈溢出。
- 跟进项：多父合并仍使用领域归约器重放祖先，不保证这类操作图的整体复杂度线性；依照验收评论保留跟进。
