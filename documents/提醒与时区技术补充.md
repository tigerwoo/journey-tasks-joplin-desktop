# 提醒与时区技术补充

调研时间：2026-10-24 00:02:39（Asia/Shanghai）。依据当前官方文档及 Joplin `dev` 分支源码；不是目标发行版本的真机验证结果。设计时需固定目标版本复核。

## 1. 插件能否独立调用系统通知

插件可以管理提醒规则、提醒列表和应用内“稍后提醒”交互。但当前公开 API 未发现可供普通插件跨桌面与 Android 使用的通用系统通知调度接口。

`showToast()` 是应用界面中的短提示，不是操作系统通知；`onNoteAlarmTrigger()` 是待办闹钟事件监听，不等于注册原生后台服务。

来源：[dialogs API](https://joplinapp.org/api/references/plugin_api/classes/joplinviewsdialogs.html)、[workspace API](https://joplinapp.org/api/references/plugin_api/classes/joplinworkspace.html)、[插件 API 入口源码](https://github.com/laurent22/joplin/blob/dev/packages/lib/services/plugins/api/Joplin.ts)。

| 能力 | 桌面 | Android |
| --- | --- | --- |
| 插件内到期提示及稍后操作 | 可设计，插件需运行 | 可设计，插件需运行 |
| 直接使用 Web Notifications | Electron 提供可验证路径，尚未在 Joplin 插件真机验证 | WebView 不支持此 API，不能照搬 |
| 原生待办系统提醒 | 宿主已有 | 宿主已有 |
| 宿主彻底退出后的未来提醒 | 当前桌面驱动依赖进程内计时器 | 已提交给原生模块的提醒具备持久调度方向，仍受系统限制 |
| 通知栏直接提供插件“稍后/完成”按钮 | 未发现公开插件入口 | 未发现公开插件入口 |

桌面插件运行在隐藏 Electron BrowserWindow 中，Electron 支持渲染进程 Web Notifications。这只是桌面可行路径的推断，不等于插件已经拥有 Electron 主进程全部通知权限或跨平台动作按钮。

来源：[Joplin PluginRunner](https://github.com/laurent22/joplin/blob/dev/packages/app-desktop/services/plugins/PluginRunner.ts)、[Electron 通知教程](https://www.electronjs.org/docs/latest/tutorial/notifications)。

Android WebView 不支持 Web Notifications/Push API，需要宿主原生实现。Joplin Android 内部确实通过原生模块调度通知，但内部模块不自动等于公开插件能力。

来源：[Chromium 官方问题](https://issues.chromium.org/issues/40388442)、[Joplin Android 提醒驱动](https://github.com/laurent22/joplin/blob/dev/packages/app-mobile/services/AlarmServiceDriver.android.ts)。

## 2. 原生提醒并不等于不能“稍后提醒”

需要纠正一个容易混淆的结论：没有通知栏“稍后”按钮，不代表插件界面不能提供该操作。可验证的混合路线是：插件保存独立任务日期和重复规则，用户在插件中选择十分钟后提醒，再修改原生 `todo_due` 让宿主重新安排通知。

Joplin AlarmService 会针对到期字段变化清除并重建提醒；真正是否按预期触发、旧通知如何清理、多端是否重复以及原生界面显示差异仍需测试。该路线不能直接承诺多个同时存在的独立提醒。

来源：[AlarmService 源码](https://github.com/laurent22/joplin/blob/dev/packages/lib/services/AlarmService.ts)、[数据 API](https://joplinapp.org/help/api/references/rest_api/)。

当前桌面驱动使用 `setTimeout()` 等待，到时显示通知，持久性返回 false。因此最小化到托盘和彻底退出不能混为一谈。Android 已调度提醒也不能代替插件尚未创建的未来重复周期。

来源：[桌面提醒驱动](https://github.com/laurent22/joplin/blob/dev/packages/lib/services/AlarmServiceDriverNode.ts)。

如果必须支持 Android 通知栏自定义操作、插件独立后台调度，需要评估扩展宿主原生桥接/API，而不是只换 JS/Rust 编程语言。此类扩展超出当前普通 `.jpl` 已公开的现成能力。

## 3. 时区不是位置

人在国外，但设备时区保持 Asia/Shanghai 时，插件不应擅自按所在地改时区。时区依据应明确，不能使用 GPS/IP 默改任务；设备自动切换系统时区也需要与“没有手动改”区分。

滴答支持“固定时区”和“固定时间”，TickTick 英文说明称后者 Floating Time。前者保留指定时区的事件语义，显示可换算；后者保持设备当地钟点，因此设备时区变化会改变实际触发时刻。

来源：[滴答官方时区说明](https://help.dida365.com/articles/7082246235360329728)、[TickTick 官方时区说明](https://help.ticktick.com/articles/7082251620645339136)。

例如上海 09:00（UTC+8）对应东京 10:00（UTC+9）。固定上海时区的任务，在设备改东京时区后可显示 10:00，但事件仍在同一时刻；设备不改时区就仍显示 09:00。浮动 09:00 则改为东京 09:00 执行。

重复任务还需保留时区中的日历规则，不能将“每天九点”一律实现为上次加 24 小时；夏令时跳过/重复钟点需确定处理策略。全天日期不应通过 UTC 午夜转换导致日期前后漂移。

本项目默认固定任务时区、是否加浮动模式仍是 D09 待确认建议；不把技术说明当作用户已选定方案。
