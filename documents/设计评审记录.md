## 2. 评审关注与修订要求

| 项目 | 结论 |
| --- | --- |
| 技术栈 | 统一纯 TS、React/ReactDOM、Temporal polyfill、lunar-typescript；不引入 Wasm、Luxon 并存或原生扩展 |
| 任务推进 | 完成或明确跳过推进，未完成且未跳过不生成；旧周期再次完成不能再次推进 |
| 日历未来可见 | 预计周期只读，不落笔记和提醒；当前未完成不隐藏未来 |
| 周期身份 | 实际周期 ID 固定；预计日程位置与实际周期分开建模，延期/改规则不能造成双计 |
| 同步保证 | 条件性最终收敛，不声称公开 API 有事务/CAS；保留用户编辑，不能只在 UI 隐藏副本 |
| 原生提醒 | 计划与单提醒字段分离，回写来源与阶段可恢复；读前检查不是无丢写保证 |
| 模板 | 插件内管理，真实笔记引用保证附件有宿主可识别的引用；载体不承诺原生隐藏 |
| 功能边界 | 无独立子任务、法定调休日历、通用模板库、统计、批量编辑、独立通知服务和浮动模式 |

### 已补充的协议细节

- 投影意图与回执通过独立不可变操作键持久化并跨端同步，携带载体代数，避免只依赖本机回声标志。
- 预计槽位 `candidateSlotKey` 与真实周期 ID 分离，真实周期记录 `originSlotKey`，规则修改维护排除映射，防止预览和真实任务双计。
- 已知依赖不完整时整系列暂停副作用，不清提醒、不转笔记类型；本机有完整创建意图的可恢复阶段与未知远端缺失分开处理。

对应测试方案已增加 C15/C16，仍未执行。
