## 1. 目标与工作方式

在 Joplin 中集中管理任务，参考滴答清单的智能清单、任务组织和日程规划方式，重点支持日期视图、重复任务、农历与提醒。法定假期与调休功能整体暂缓，普通工作日/周末保留。

按用户要求：先完整讨论和确定全部需求，再一次性开展开发；不划分首期或 MVP。本文中的功能分类用于区分已确认要求与候选功能，不代表分期开发。

本阶段仅维护文档，不编写代码，不决定 TS/Rust/Wasm。所有需要用户回答的问题统一写入 [讨论记录.md](讨论记录.md)，本文只引用问题编号。已答复内容以讨论记录中的用户原文为依据。

## 3. 功能状态

- **已确认：** 第 2 节列出的要求。
- **默认设计：** 对用户未逐项选择、且未提出异议的边界行为，明确标为设计默认值，不伪称用户逐项确认。可进入技术设计评审，不重复增加需求问卷。
- **暂缓：** 未选入的调研功能保留档案，不纳入本次交付。
- **排除：** 正文复选框接管、独立子任务系统，不因参考滴答而重新纳入。

## 4. 任务与笔记

### 4.1 管理单位

执行任务以 Joplin 原生待办笔记为单位；持续模式复用同一篇，周期归档模式每周期独立待办。系列规则、模板编辑和周期操作由插件界面提供；底层模板持久化及同步方式仍待设计，不等于必须暴露为用户普通笔记。

普通笔记中的 `- [ ]`、`- [x]` 是正文检查项，用户可将其作为内部步骤使用。插件不自动提取、重置、勾选、统计或为它们创建独立日期和提醒。父任务完成也不自动改写正文检查项。

### 4.2 基本操作与默认设计

- 新建任务，输入标题、所属笔记本、日期和可选时间。
- 编辑、完成、撤销完成、删除任务；普通任务可改期，重复任务通过系列规则编辑或临时延期调整，不提供任意单次改期。默认不允许在维持有效重复规则时清空系列基准日期；取消重复和清除日期需通过明确操作分开处理。
- 打开原始待办笔记，使用 Joplin 编辑正文、图片和附件。
- 显示来源笔记本、标签、优先级、重复与提醒标识。
- 重复任务可跳过本次、结束重复；删除或修改时明确作用范围。
- 插件与原生待办界面的标题、状态、原生日期修改应相互反映。
- 不对用户未纳入管理的普通笔记进行隐式转换或修改。

### 4.3 任务信息

| 字段 | 状态与说明 |
| --- | --- |
| 标题、完成状态、原始笔记链接 | 基础操作 |
| 计划日期、全天/具体时间 | 日期视图所需；映射方式在技术设计中明确 |
| 提醒 | 原生提醒，插件管理字段；不新增多重提醒或独立通知服务 |
| 优先级 | 已确认；高、中、低、无四档，并提供文字或图标，不能只靠颜色区分 |
| 重复规则、历法、规则生效范围 | 已确认功能所需 |
| 所属笔记本、标签 | 使用 Joplin 现有组织体系；插件内扩展编辑与筛选暂缓 |
| 周期完成与跳过记录 | 必要执行记录已纳入；不扩展为 C09 统计模块 |
| 开始/结束时间、预计时长 | 暂缓，不将原生提醒字段强行解释为时间段 |

## 5. 智能视图与日历

### 5.1 视图

| 视图 | 状态 | 行为 |
| --- | --- | --- |
| 今日 | 已确认 | 按当天自然日归类，提供逾期显示选项 |
| 未来七天 | 已确认 | 日期 T 至 T+6；例如 10 月 23—29 日，30 日不在范围内 |
| 月视图 | 已确认 | 月历定位日期、查看当日任务、切换月份、回到今天；建议点击日期新增任务 |
| 年视图 | 已确认 | 年度日期概览、按日查看任务并进入具体日期；小屏避免堆叠完整任务文字 |
| 全部、无日期、逾期、已完成 | 暂缓（Q06） | 便于收集、补安排和回顾 |
| 明日、最近添加 | 暂缓 | 快速安排近期任务 |
| 周/日时间轴、看板、四象限、时间线 | 暂缓 | 选择范围见 Q06，不与已确认月/年视图混为一谈 |

### 5.2 日期与显示细则

- “今日”按设备本地自然日，不按过去 24 小时计算。
- 七天区间为 `[T 日 00:00, T+7 日 00:00)`；逾期若启用则单列，不改变七天区间。
- “显示逾期”可在页面直接切换，今日与七天分别记忆；月/年不把历史逾期任务重复投影到今天。
- 无日期任务不自动归入今日；完成记录与未完成任务区分。
- 全天任务在其日期结束后逾期，定时任务到点逾期；采用固定任务时区，详见第 5.3 节。
- 午夜跨日、恢复前台、笔记修改、同步完成后更新归类。
- 列表与日历呈现同一套任务；同一周期在同一视图不重复计数。
- 农历日期支持并列展示。月/年等日历必须展示可见范围内的未来预计周期，用独立标记与实际任务区分；未完成当期不能成为隐藏未来日程的理由。
- 未来周期预览不提前创建待办笔记，计算、缓存与性能处理留到技术设计；预览默认只读，提前操作不作为已确认需求。
- 无任务、加载、失败和无匹配结果均有明确状态，不能把失败误显示为无任务。
- 扩展分组排序配置暂缓；为基础可读性保留按日期的稳定排序，不扩展为自定义筛选系统。

### 5.3 固定任务时区

- 创建定时任务时默认使用设备当前 IANA 时区，并保存任务时区；既有任务不因设备时区改变而被重写。
- 不根据 GPS/IP 等地理位置自行换时区。设备时区未变时，不因用户出国而改变显示或提醒。
- 设备时区改变时，可显示对应本地时间及任务原时区，保持同一实际事件时刻；重复按任务时区的日历钟点计算。
- 全天任务保留日期本身，不因 UTC 换算前后漂移。
- 不提供浮动时间模式。夏令时的缺失/重复钟点处理属于技术设计默认值，需写入设计规范并测试。

## 6. 展示位置、默认视图与记忆

- 桌面默认在界面右侧使用 Agenda 同类插件侧面板，可同时编辑笔记；用户移动面板后保留布局，不反复强制归右。
- Android 保留支持目标，采用宿主插件面板作为适配方向；用户尚未安装测试，入口与体验待实测，不要求现在补答。适配窄屏触摸，不依赖悬停或桌面快捷键。
- 支持面板显示/隐藏、浅色与深色主题；保留用户调整后的布局，不每次重置。
- 提供默认打开视图设置，至少包括今日、未来七天、月、年。
- 启动模式可选“指定默认视图”或“恢复上次视图”，按所选模式执行；不同时争抢。面板默认展开。
- 视图与布局偏好按设备保存，任务与规则跨端同步。月/年在应用启动时定位今天所在月/年；仅隐藏再打开面板则保留浏览位置。

## 7. 重复任务

### 7.1 规则范围

重复与普通工作日已确认；下列普通规则集作为 D02 延续的默认设计，用户本轮强调未来日历展示，具体实现回头讨论。法定调休已明确暂缓。

| 规则 | 例子 |
| --- | --- |
| 每日与间隔 | 每天、每两天 |
| 每周与指定星期 | 每周一三五、每两周 |
| 每月 | 每月 15 日、每月最后一天、每月第 N 个星期 X |
| 每年 | 公历每年某月某日 |
| 普通工作日 | 周一至周五，不自动视为法定工作日 |
| 法定工作日（暂缓） | 已明确不纳入本次交付 |
| 普通周末 | 周六、周日 |
| 法定休息日（暂缓） | 已明确不纳入本次交付 |
| 农历每月/每年 | 初一、十五、农历生日等 |
| 结束条件 | 一直重复、截止日期、限定次数 |

默认支持按计划日期和按完成日期两种基准，默认按计划日期；结束可选永久、截止日期（含当天）或次数。跳过占一次，撤销后再完成不重复计数。以上为设计默认值，不标记为用户逐项确认。艾宾浩斯等扩展暂缓。

### 7.2 已明确的周期操作

- 不支持重复任务的单次改期；编辑日期等系列属性按系列修改处理，历史不回写。
- 提供“延期”操作，只将当前任务临时延后，不修改原重复锚点、规则或默认模板；不将此操作包装成任意改期。
- 当期既未完成、也未明确跳过时，不生成下一周期实际任务。完成或明确跳过后才推进一次；日历仍必须显示标明身份的未来预计周期。
- 完成本次或跳过后才推进系列；不存在的公历日期取对应月最后一天，包含 31 日遇小月、2 月 29 日遇平年。
- 撤销完成只改变对应任务/执行记录状态，不自动删除或重算后续任务。默认已推进的旧周期再次完成不推进；A 模式改历史记录不回退承载当前周期的笔记。后继已编辑或完成也不得丢失。
- 延期默认同步移动相对提醒。按计划重复跨过多期后，默认从原规则取严格晚于本次实际处理时刻的下一次，不连续补建过期任务；跨过周期不记为完成。按完成日期基准则从实际完成时刻计算。
- 上述撤销、延期和漏期处理为 D02 默认设计，具体算法、预览与同步并发机制在技术设计中验证。

### 7.3 中途修改重复规则

- 系列编辑对当前及未来生效，不修改既有历史内容；已产生且被用户编辑的后续任务不得静默覆盖。
- 保存前展示规则和下次日期预览；修改历法、基准、间隔、结束条件时检查剩余次数与锚点。
- 用户不接受任意单次改期，旧版“未来单次改期例外”设计撤回，保留“临时延期”这个明确入口。
- 在生成受限的情况下仍需处理撤销后存在多个未完成周期，以及同步冲突。技术设计需明确活动周期与历史状态的区别，并验证去重。

### 7.4 已确认的笔记模式与模板

- 创建重复系列时可选 A 持续模式或 B 周期归档模式；后续允许切换，只影响未来，不改写历史。默认 A，创建时显式展示 A/B；切换从下一次推进/生成生效，当前内容不即时复制、合并或删除。
- A：同一笔记记录持续过程，完成本周期后推进下一次；必要执行记录由插件保留，不提供独立统计模块。
- B：本次待办保留当期正文与完成结果；下次任务从系列默认模板创建，不复制上次执行过程作为默认模板。
- 每个 B 系列有可编辑的默认模板；模板修改用于以后新建任务，不覆盖已经生成的任务与历史。
- 模板在插件内管理并随系列同步，不作为普通待办展示。标题、正文和附件引用取模板；优先级、重复、提醒取系列设置；不继承上次执行状态和记录。标签与笔记本沿用系列来源值。附件引用保持有效，不逐次物理复制。B 历史保留在原笔记本，不自动归档。通用模板库 C06 暂缓。
- 插件不自动重置既有正文复选框。B 新任务保留模板原样，与改写历史检查项是两回事。

## 8. 农历（已授权设计并明确以下规则）

支持农历选择、公历对照、农历每月/每年重复、闰月标记及有效日期校验。保留农历原始规则，不能只转换一次后改用公历年度重复。

| 边界 | 产品规则 |
| --- | --- |
| 普通月年度重复 | 仅普通月，不在同名闰月多执行一次 |
| 闰月日期年度重复 | 有对应闰月则用闰月，无对应闰月则用同名普通月；摘要清楚标记回退 |
| 农历每月重复 | 闰月作为独立月份参与序列 |
| 三十遇小月 | 取当月最后一天，不溢出到下月 |
| 除夕 | 使用农历年最后一天规则，不固定为腊月三十 |
| 转换时区 | 农历历表换算以 Asia/Shanghai 为基准；提醒展示与定时任务时区分开 |
| 年份覆盖 | 目标支持公历 1901—2099 内可转换日期，具体边界经库与独立历表验证；无法计算下次时明确提示 |

以上是用户授权后的设计决定，不宣称所有软件都采用相同惯例。验证不支持时需说明并调整设计，不伪造结果。

## 9. 法定假期与调休（已确定暂缓）

D04 明确选择 A：法定假期/调休重复整体暂缓。本次仅支持普通周一至周五与周末，不提供法定工作日/休息日规则、假期数据更新、导入或手工覆盖。不用普通工作日冒充法定规则。

## 10. 提醒

### 10.1 已确认方案

使用 Joplin 原生提醒，由插件维护笔记提醒字段，宿主负责系统通知投递；不开发独立通知服务、原生桥接或定制客户端。

插件管理到期、延期、完成、跳过及下周期生成时的提醒字段更新；不保留旧提醒或重复推进。应用打开且插件启用是插件运行的前提；移动端被挂起时不能假定插件仍持续运行。

### 10.2 范围与技术设计事项

- 单条原生提醒为交付基础，不扩展多个同时提醒、通知栏自定义按钮、持续响铃或位置提醒。
- 稍后提醒可在插件内通过更新原生字段实现，不承诺通知栏直接操作；实际重调度、去重与显示映射由技术验证确认。
- 原生 `todo_due` 同时涉及待办日期与提醒。任务计划、延期、稍后提醒及原生编辑的字段映射必须在设计规范说明，不让提醒变动悄悄改变重复锚点。
- 全天任务不无提示设置午夜通知；提醒默认时刻、未设置状态和字段同步采用明确的设计默认值，不另增产品功能。
- 通知权限、宿主退出/后台限制、设备重启与多端通知需真机验证，不宣称保存字段即可保证通知必达。
- 不要求插件退出后自动生成后续周期；仅已交给宿主调度的提醒由宿主能力决定。

## 11. 滴答功能参考与候选扩展

## 12. 多端、离线与数据保护

- 核心任务、重复、农历规则离线可用，经 Joplin 正常同步流程跨端传播。
- 任务和周期规则不只保存在单台设备；面板位置等设备偏好与任务数据分离。
- 两端同时完成同一周期，不产生两份后续周期；并发修改规则不静默覆盖历史。
- 同步冲突保留可恢复信息，重试不会重复应用操作。
- 不扫描接管正文复选框；删除任务或系列前明确笔记和历史的影响范围。
- 停用插件后原始笔记可访问；重新启用识别原生修改，不无限补建遗漏周期。
- 原生待办转换为普通笔记、移入回收站、恢复、移动笔记本时，插件对应更新，不擅自恢复已删除任务。
- 月/年视图仅按可见范围生成预览，不无限生成远期笔记；性能目标在需求定稿时结合真实任务量确定。

## 13. 验收场景

目前仅为用例草案，没有实现或测试通过记录。候选功能只有选入后才纳入最终验收。

| 编号 | 场景 | 验收要点 |
| --- | --- | --- |
| A01 | 原生待办与正文复选框 | 原生任务互通；正文检查项不被自动提取、重置或改写 |
| A02 | 今日与未来七天 | 包含当天，正确跨月/年；逾期开关即时生效；隐藏不改变状态 |
| A03 | 月/年视图 | 当期未完成时仍可见未来预计周期；不提前生成笔记；日期、农历与预览一致，窄屏可操作 |
| A04 | 视图启动策略 | 指定默认/恢复上次按确认优先级执行；重启不丢偏好 |
| A05 | 优先级 | 保存、修改、跨端一致；颜色之外可辨识 |
| A06 | 普通工作日 | 周一至周五正确执行，不冒充法定调休规则 |
| A07 | 法定日历 | 明确暂缓，不作为本次必须通过的用例 |
| A08 | 修改重复规则 | 历史不变，未来重算，延期不改系列锚点，已编辑未来笔记按规则处理 |
| A09 | 完成、撤销、跳过与漏做 | 未完成且未跳过不推进；跳过必须推进；旧周期再完成不重复生成；历史和次数正确 |
| A10 | 月末与闰年 | 31 日、小月、2 月 29 日按确认规则处理 |
| A11 | 农历特殊日 | 闰月、小月三十、除夕、春节跨年用独立历表核对 |
| A12 | 原生提醒 | 桌面/Android 设置、改期、完成、删除后通知调度正确，无残留旧提醒 |
| A13 | 通知权限与生命周期 | 拒绝权限、锁屏、宿主退出、重启、离线时的能力与提示符合约定 |
| A14 | 多端并发 | 双端离线完成同一周期后只有一个后续周期；规则冲突可恢复 |
| A15 | 重复笔记模型 | 按已确认 A/B 模式保留链接、正文、附件与执行历史，不擅自重置内部检查项 |
| A16 | 外部修改与停用恢复 | 原生完成/改期/删除被识别，重启和重复同步不重复应用 |
| A17 | 系列默认模板 | B 模式新周期取模板最新内容，已有任务不被覆盖；C11 快捷操作不接管正文检查项 |
| A18 | 默认面板位置 | 按确认的 Agenda 参照核验桌面位置和移动入口，用户布局不被重置 |
