# Joplin 任务管理增强插件设计规范

## 0.5.5：系列一致性约束（Issue #32）

1. 两种创建入口共用系列初始化；不同编辑入口更新同一状态，只有一套重建与推进逻辑。
2. 周期身份、规则位置、单次执行日期分别管理。规则修订按因果关系重放；进入历史后不能恢复成创建时的旧计划，其他字段编辑不能覆盖日期。
3. 计划重复逐期推进，允许下一期逾期；完成重复以处理日期为基准。实际推进、未来预计和编辑预览共享计算；一次操作只生成一代。
4. 显式改名作用于整个系列及已生成的中间/历史笔记标题；正文、时间和终态保持不变。同名但不同系列的笔记不受影响。部分失败有待处理数量和持久化回执。
5. 普通、归档、持续任务的放弃均保存结果，按已处理记录展示专用标识；持续历史按周期展示，不能操作到共享笔记的另一个周期，也不产生历史提醒。
6. 系列始终关联原始首篇。模式只决定复用或创建执行笔记；旧锚点转移按完整日志校验归回首篇，原始首篇缺失或冲突时暂停。
7. 修复既有日志的日期解读，不自动删除笔记或补建历史推进链。无法从旧普通任务的单一完成时间恢复其放弃类型。

下文的旧版跳过逾期、首篇标题隐含决定系列名及模式迁移数据位置等描述以本节为准。


## 0.5.4：重复周期与原生状态协调（Issue #29）

本节为当前行为，优先于下文早期设计中关于跳过、延期、历史撤销和模板初始化的描述。

- 完成和放弃仅允许任务时区今日及过去日期；无日期普通待办可完成。跳过统一为放弃，内部旧 `skip` 日志继续读取，原生保持已完成待办，不追加正文。
- 当前周期只有一个推进资格。撤销最近一次处理使用 `RewindAdvance` 同时撤销终态与对应推进边，下一期退出实际任务、取消提醒并保留笔记；再次推进相同周期优先复用。更早历史只改结果，不撤回后续链。
- `withdrawn` 由有效推进链可达性推导，不把保留后继误收为普通待办；未来预计不抑制已撤回周期日期。持续模式以当前周期优先选择共享笔记的原生状态投影。
- 撤销日志必须因果观察目标完成与推进；后继并发推进时暂停冲突。恢复创建前检查推进是否仍有效，已撤销的创建不重放。恢复状态只修改原生字段，不修改既有标题或正文。
- 原生合法完成照常推进；未来完成只恢复 `todo_completed` 并通过宿主消息框告知。依据完成时间及任务时区判断，避免延迟同步把早完成当合法完成。插件停用期间无法事前拦截；状态纠正回声不再触发推进。
- 去掉延期界面和命令，保留旧请求格式兼容。日期修改只改本次计划；编辑规则重新计算当前及未来预计，保留笔记内容和历史。无有效当前候选时拒绝规则保存并提示调整日期/结束条件。
- 归档模板启用只读取，不初始化执行副本；持续切换不剥离模板。显式插入模板、用户主动编辑标题仍按操作执行。新建归档后继可从模板写入初始内容。
- 快照过期时，面板仅在目标任务及系列未变化的情况下保留请求 ID 重试一次；真实变化仍拒绝，避免操作落到新周期。
- 安装同一新版后再跨端使用；旧版本不理解新增撤销操作，不能与新版混用管理同一系列。

## 1. 设计目标与范围

使用纯 TypeScript 实现一个 `.jpl`，支持桌面与 Android。插件运行代码编译为 JavaScript，不引入 Rust/Wasm、原生模块、独立通知服务或定制客户端。iOS 只保留 API 兼容方向，分发仍受官方推荐插件限制，不写成已验证支持。

覆盖原生待办、今日/七天/月/年视图、未来预计周期、重复、农历、四档优先级、原生提醒、A/B 模式与系列模板、必要执行记录及 C11 快捷交互。法定日历、通用模板库、独立子任务、批量/筛选/统计等按需求暂缓，不能借架构设计重新加入。

本设计不修改用户维护的需求文档。若验证表明公开 API 无法达到某项已确认体验，先给出具体限制和替代方案，再在讨论记录中收敛；不默默降低验收要求。

### 1.1 关键设计决定及原因

| 决定 | 原因 |
| --- | --- |
| 纯 TS、浏览器兼容依赖 | 当前功能以 API、日期计算与界面为主；减少 Android 适配面，不提前优化未测瓶颈 |
| 原生待办作为执行正文载体，插件元数据保存计划语义 | `todo_due` 同时触发提醒，无法独自表达“有日期但不提醒”和“稍后提醒但不改计划” |
| 普通任务自身、重复首篇自身 userData 承载元数据 | 不产生辅助笔记；用户接受首篇作为系列生命周期锚点；模板放无附件 JSON 快照 |
| 每操作一个不可变 userData 键，快照可重建 | userData 按键合并，不把两个设备修改整个 JSON 的最后写入当作安全合并 |
| 周期逻辑 ID 与原生笔记 ID 分离 | A 复用笔记、B 每期换笔记；日期修改、延期不能改变周期身份 |
| 未来周期为只读纯计算结果 | 用户要求看得到未来，不要求提前生成；避免僵尸任务与远期通知 |
| 明确最终收敛及恢复流程 | 公开 API 没有跨操作事务、CAS 或跨端互斥；本地锁不能保证离线全局唯一 |
| 并发规则冲突暂停自动推进，保留分支 | 规则决定未来内容与日期，静默选一个版本会破坏用户数据 |

## 2. 宿主能力与已核验事实

只使用公开插件 API；源码用于确认边界，不能直接导入宿主私有类。2026-10-24 在线查阅的 `dev` 分支是设计依据，不是目标版本兼容性的证明；实现时需记录实际 Joplin 版本及对应源码提交。

| 能力 | 设计依据 | 限制 |
| --- | --- | --- |
| 笔记 CRUD、分页、userData | `joplin.data`，无需 Clipper token | 没有公开跨笔记事务或条件更新接口 |
| userData | 以插件 ID 为命名空间、键值同步、按键时间戳合并 | 同键更新会覆盖；不能作分布式锁；数据布局枚举需适配 |
| 面板及消息 | `joplin.views.panels`；移动为宿主标签对话框 | 推送消息未监听时会丢；手机不是桌面永久侧栏 |
| 原生提醒 | `todo_due` 与未完成待办关联，由宿主调度 | 不新增多个提醒或系统通知动作按钮 |
| 桌面提醒 | 当前源码为进程内定时器，触发后显示系统通知 | 彻底退出与托盘运行不同，退出后不继续计时 |
| Android 提醒 | 当前驱动调用原生通知模块，标记支持持久调度 | 已提交提醒不等于插件能在后台继续算下一期；强停/重启需实测 |
| 插件设置 | `joplin.settings` 可保存设备偏好 | 不将本机设置当作跨端任务唯一存储 |

来源：[S01]—[S08]。未确认的能力必须由第 15 节验证门槛解决。

```text
    └── panel          React + TS + HTML/CSS，消息协议，今日/七天/月/年
```

领域层不得调用 `joplin.*`、系统时间、DOM、随机数或网络；时钟、ID、日历和持久化经接口注入。`services` 是应用服务层，写入口只有命令处理器；面板不能直接写笔记。查询和预计周期计算不得调用 mutation 接口。

运行依赖采用已锁定的 React/ReactDOM，日历使用 Intl 适配器。重复规则在领域层实现；ES2020 与宿主 Intl/Chinese calendar 支持仍需目标环境核验。原 Temporal/lunar-typescript 候选被本节实现修订替代，不再额外安装。

禁止运行时依赖 Node 的 `fs`、`path`、`electron`、SQLite 原生包；构建期使用 Node 不受此限制。禁止直接读写 Joplin 数据库文件或同步目标。

## 4. 最小领域模型

以下为接口设计，不是功能源码。所有持久对象均带 `schemaVersion`；所有标识使用区分大小写的稳定字符串，不从标题推导。

### 4.1 身份与日期

| 类型 | 字段及不变量 |
| --- | --- |
| `SeriesId` | 创建系列时分配，永久不随标题、模式、规则改变 |
| `OccurrenceId` | 首期由 `seriesId + "root"` 派生；后继由 `seriesId + predecessorOccurrenceId + "next"` 派生，采用带域前缀的 SHA-256；不是原生笔记 ID |
| `CandidateSlotKey` | 预计槽位身份：`seriesId + ruleRevisionId + 原计划公历/农历选择器位置 + 当地钟点 + zone`；与 OccurrenceId 不同，不要求预先知道未来链条 |
| `OpId` | `deviceId + 本机单调序号 + 随机后缀`，写前持久化；重试沿用同一个 ID |
| `RuleRevisionId` | 规则变更操作的 ID；修改基于显式父版本，不以时间戳选规则 |
| `DateOnly` | `YYYY-MM-DD`，不通过 `new Date("YYYY-MM-DD")` 隐式转换 |
| `TaskDate` | 无日期；或全天 `{date, zone}`；或定时 `{localDate, localTime, zone, instantMs, offsetMinutes}`。`zone` 为保存的 IANA 名称 |

相同逻辑后继即使两端计算出不同日期，也有同一个 `OccurrenceId`，便于发现分歧，而不是把它们误认成两个正常周期。哈希用于稳定身份，不提供事务或同步互斥。

### 4.2 系列、周期与原生映射

| 实体 | 核心字段 |
| --- | --- |
| `SeriesDefinition` | `seriesId, revisionId, parentRevisionIds, rule, anchor, taskZone, reminderPolicy, priority, pinned, modeForNext, templateRevisionId, sourceNotebookId, sourceTagIds, endCondition` |
| `SeriesRuntime`（派生） | `activeOccurrenceId, activeCarrierNoteId, consumedCount, advancementEdges, status(active/ended/pausedConflict/missingCarrier), unresolvedConflicts` |
| `Occurrence` | `occurrenceId, seriesId?, predecessorId?, originatingRevisionId, originSlotKey, suppressedSlotKeys[], scheduledDate, deferredDate?, resolution, consumed, carrierNoteId, createdBy, reminderOverride?` |
| `resolution` | `open/completed/skipped`，完成含实际完成时刻；跳过与完成分开，不能把跳过伪造成原生完成 |
| `consumed` | 此周期是否已经用来推进/结束系列，一旦确认不因撤销变回 false |
| `TaskBinding` | 原生 `noteId` 对应 `occurrenceId`、系列和载体角色；A 中同一 noteId 会被绑定到不同当前周期，B 中逐期不同 |
| `TemplateRevision` | `templateRevisionId, seriesId, parentRevisionId, title, body, resourceIds, contentHash, noteId`；已发布版本不可原地覆盖 |
| `ProjectionIntent/Receipt` | `intentId, noteId, occurrenceId, carrierGeneration, nativeBefore, nativeAfter, sourceOpId, projectionVersion, phase, bodyHashAtCreation`，用于恢复和外部修改判别；Receipt 另含 readbackHash/observedAt |

单次普通任务也具有稳定 `taskId/occurrenceId`，但没有重复规则和后继。默认读取全部可访问的原生待办以展示；没有插件计划的既有待办采用 `todo_due` 导入视图：非零时间戳显示为定时任务，未知“全天”语义不自行推断。首次写入管理元数据前保留导入快照。

### 4.3 规则结构

`RecurrenceRule` 保存 `calendar(gregorian/lunar), frequency(day/week/month/year), interval(正整数), basis(scheduled/completed), selectors, missingDatePolicy(lastDay), lunarLeapPolicy, endCondition`。星期采用 ISO 1—7，周一为周起点。

- 日：每 N 个自然日；普通工作日为星期集合 1—5，周末为 6—7。
- 周：锚点所在周起，每 N 周中匹配所选星期；单日默认锚点星期，多选不产生同日重复。
- 月：每 N 个月匹配指定日、月末或第 N 个星期 X；年：锚点起每 N 年匹配月日。
- 所有步进从规则原始锚点推算，不能从上次钳制后的日期继续加月，避免“1 月 31 → 2 月末 → 3 月末变成 28 日”。
- “第 5 个星期 X”当月不存在时，设计默认取当月最后一天，并在规则摘要标明；与“最后一个星期 X”是不同选择。此项遵循日期不存在取月底的产品默认，必须设独立测试。
- 结束次数按已消费的实际周期计数，完成或显式跳过消耗一次；自动越过的过期日程只记略过区间，不伪造周期笔记、不消耗次数。规则编辑继承已消耗次数，剩余为零则不再推进。
- 截止日期按任务时区的日期比较，包含当天；农历规则也将换算后的执行日期与截止日期比较。

## 5. 持久化、同步载体与附件

### 5.0.1 最新授权：仅保留 template 界标（覆盖下方旧双区协议）

用户在首篇正文自行定义一对独占行 `<!-- template:start -->` / `<!-- template:end -->`。不加 execution 标签，不自动包 Markdown 围栏，不兼容旧双区格式。首次开启归档必须有合法模板块，插件把块内原文复制插入 start 之前，保留原文和所有块外文本；后续原生编辑模板只影响新后继，标题取首篇原生 title。模板内检查项也会作为普通 Markdown 显示，这是本次用户明确选择的格式。

`parseArchiveBody` 返回 `templateBody/prefix/suffix`；prefix 与 suffix 为模板整个块以外的逐字符原文。移除模板只拼接 prefix+suffix，不吞块外换行。`initializeArchiveBody` 仅为纯字符串转换，每次调用会复制，业务层负责只初始化一次。`ensureSource(seriesId,locale?,initializationId)` 使用独立不可变 hash-only prepare/done 回执：写前保存原正文哈希及目标正文哈希，写后保存完成回执；回执键按承载 note+initializationId 寻址，不含可能重试时变化的 seriesId；首次配置使用由 noteId 派生的稳定初始化 ID。同 ID 重试检测目标哈希补回执，原哈希则继续，否则暂停保护并发编辑。A→B 新初始化须传稳定的新操作 ID。userData 不存业务模板正文。新建归档在 POST 前初始化最终正文，后续不再次初始化。只读 `readSource` 从不修改正文。

所有真正位于围栏代码/缩进代码中的 marker 示例忽略；重复、残缺、逆序、未知保留 marker 或旧 execution marker 一律报 TEMPLATE_FORMAT。模板可包含自身代码围栏，但其关闭必须完整以便 end marker 可识别。

### 5.0 v3 当前有效存储与重锚协议

用户授权开发期直接重构，不迁移 v1/v2 数据。当前存储版本 3，领域操作仍 schema 1；`src/shared/storageVersion.ts` 独立导出 `CURRENT_STORAGE_VERSION=3`，避免本机设置与仓储循环依赖。scope/op/carrier/pending 前缀全部使用 `v3:`。不在任何 userData 键写业务模板正文或完整模板快照；模板来源仅保存首篇 ID、选择器和内容哈希等元数据。

正文格式、初始化及清理以本节前的 5.0.1 短 template pair 协议为唯一现行依据。0.4.0 的 execution 四界标、模板外围 Markdown 围栏及自动双区复制方案已废弃，解析器拒绝该旧格式，不迁移。`readSource` 每次重新读取首篇 title 与模板块原文；规则/推进仅记录 sourceNoteId/hash，不存正文。

B→A 在下一次推进时复用当前执行载体作为独立持续根，不额外创建一篇任务；必要规则/操作元数据转移到当前载体，正文拆区并去除首篇保留提示。已消费历史载体缺失不再阻断持续任务。旧首篇删除不得影响已完成转移的持续任务。

`JournalRepository.reanchor(seriesId,targetNoteId,transferId): Promise<ControlMeta>` 只转移元数据，不复制正文/模板。先写目标准备 scope，复制日志后写可校验的目标 commit（含系列/目标身份、ancestorNoteIds、日志 ID/哈希）；不写旧根 redirect，使用已提交目标的祖先集合排除旧根；目标 commit 自足，不以旧根仍存在为条件。discover 根据已提交的转移链选择唯一最新根，未提交目标或并发分叉只读暂停，不选两个主源。中断可按 transferId 重放；目标提交后旧根消失也可发现新根。无跨端事务，部分同步/并发期间仍可能临时看到冲突，不能承诺强一致。

当前模式定义决定是否依赖首篇模板。持续模式自身就是唯一载体，无“请勿删除系列首篇”说明；归档模式才提示保留首篇。首篇同时执行第一期与模板源，因此用户主动编辑首篇会改变首篇本身；只承诺已有后继历史不被改写，不宣称首篇历史不可变。

验收覆盖原文/代码示例完整往返、短 template pair 与无外围围栏、原生模板修改只影响之后生成、损坏界标失败关闭、userdata 无完整模板正文、B→A 不增笔记/新根独立存活、转移中断/分叉，以及清理保留区外日志。

#### v3 载体转移提交与故障窗口

`reanchor(seriesId,targetNoteId,transferId): Promise<ControlMeta>` 不创建笔记。目标 `v3:scope:<seriesId>` 先写入带 `transferId/ancestorNoteIds/anchorGeneration` 的准备标记，然后逐条复制不可变 op；最后写 `v3:anchor-commit:<seriesId>:<transferId>`，内容仅为身份、祖先 ID 和 `operationHashes`（整个 op 的哈希），不含模板正文。目标 scope 无完整 commit 或清单任一 op 尚缺时不能当主载体，旧主仍有效；提交后即使旧主无 redirect、随后被删除，目标仍独立有效。

发现阶段收集所有有效候选，按已提交目标的祖先集合排除旧主；剩余多个不相关主载体是并发转移冲突，暂停而非按时间择胜。转移之后旧主若同步到目标没有的 op 或同 ID 异值，保留双方日志并暂停该系列，普通扫描不自动修复，不承诺事务或跨端即时一致。用户显式重试先调用 `mergeRetired(seriesId)`：扫描并验证唯一完整提交主载体，先校验全部可用旧/新日志的 op 身份与完整哈希，同 ID 异值或并发多主则拒绝且不写；兼容的缺失 op 逐条不可变追加到新主，不改正文、原生字段或原 commit。中断可重试，之后归并领域状态；领域业务冲突仍走既有解决流程。缺失/已删除旧主无法恢复未同步日志，不能删除旧主来假装合并成功。准备写入中断可使用同目标、原 transferId 重试；一旦提交不能重写其清单。

### 5.1 任务自身与首篇锚点

不新建任何专用数据笔记本、控制笔记或模板笔记。普通任务自身保存其 single 作用域；重复系列的真实首篇保存 series 作用域、模板快照和执行日志。首篇可以是未完成待办、已完成历史或跳过后的普通笔记，只要仍存在且可读即为合法锚点；不能要求控制载体必须 `is_todo=0`。

`registerBinding(seriesId, rootNoteId)` 建立本机查询映射；`controlId(seriesId)` 返回实际首篇 ID，未注册时明确失败，不再按 seriesId 哈希出一篇辅助笔记。`createControl(meta)` 只向既存首篇追加作用域元数据，不创建、重建或改写正文。普通转重复后 single/series 作用域可共存在同一首篇，执行身份与锚点身份不互斥。

首篇的用户正文与模板快照分离。提示“请保留系列首篇”仅添加一次，不进入模板、不逐期复制；规则与日志不放进正文大段 JSON。后继以稳定 ID 关联首篇，改名/移动不破坏关联。

### 5.2 键约定与操作集合

存储封装版本为 **2**，领域操作 schema 仍为 **1**。当前写入全部使用新前缀 `v2:`，仅写本插件命名空间，每键不可变；重试必须同 ID、同哈希，不覆盖其他作用域或插件。精确键契约：

| 键 | 值与位置 |
| --- | --- |
| `v2:scope:<scopeId>` | `ControlMeta{schemaVersion:2,role:single/series,seriesId,rootNoteId}`，写实际任务/首篇 |
| `v2:op:<scopeId>:<opId>` | 原 domain/single 操作对象（schemaVersion:1），写该 scope 的实际锚点 |
| `v2:template:<seriesId>:<revisionId>` | 完整 `TemplateRevision` JSON（schemaVersion:1、noteId=实际首篇、resourceIds=[]），写首篇 |
| `v2:carrier:<seriesId>:<occurrenceId>` | `CarrierMeta`（schemaVersion:2、anchorNoteId、逻辑身份、最小计划快照），写首篇或后继的实际执行笔记 |
| `v2:pending:<seriesId>:<occurrenceId>:<opId>` | 首篇暂不可用时的本次完成/等待推进证据，写尚存后继；不可冒充完整系列备份 |

`operations(note, scopeId)` 按作用域读取；一篇笔记具有多个 scope 而调用方未指定时拒绝混读。模板 publish 先注册首篇绑定，按快照键保存；`loadRevision(seriesId, revisionId)` 明确按首篇+版本寻址，不再派生模板笔记 ID。后继快照仅供首篇不可用时显示与完成，不含复制的规则/模板，不自动成为第二个权威系列源。

实际键通过仓储导出的 `scopeKey/operationKey/templateKey/carrierKey/pendingKey` 构造，scope 分量使用 encodeURIComponent，避免含冒号的 scope 互相前缀匹配；领域哈希身份保持不变。清理应遍历本命名空间所有键（包括 d 删除标记），不能只使用读取活跃键的方法。当前作用域 journal 的本机 outbox phase 为 `v2:journal-pending:<scopeId>` / `v2:journal-saved:<scopeId>`，只重放这一新格式且需首篇作用域身份仍然存在；旧 auxiliary outbox 不迁移、不重放。

最小操作集合：

| 操作 | 内容 |
| --- | --- |
| `CreateSeries` | 初始定义、首期 ID、来源笔记与导入快照 |
| `ReviseSeries` / `ResolveSeriesConflict` | 父规则版本、完整新定义；后者显式引用待合并分支 |
| `ActOccurrence` | `complete/skip/reopen/defer/snooze`，目标周期、观察到的状态版本、参数；reopen 显式引用被撤销结果 |
| `SetTaskFields` | 优先级/置顶/单次任务计划等，按字段保存，正文不进入此操作 |
| `Advance` | 前驱 ID、消费依据、后继 ID 或结束、选用规则/模板版本、计划日期、跳过日期范围、候选笔记 ID |
| `BindCarrier` | 周期与实际 noteId、创建内容哈希、生成依据及候选角色 |
| `ProjectionIntent` / `ProjectionReceipt` | 每个原生写阶段的 expected before/after，完成读回的共享回执；与 sourceOpId/载体代数关联 |
| `StopOrDelete` / `Restore` | 明确范围的停止/删除/恢复意图，不把单次 GET 404 当作永久删除 |
| `ObserveNative` | 外部变更的 before/after 指纹及解释，避免同一原生变更反复导入 |

操作公共头：`schemaVersion, opId, deviceId, deviceSeq, seriesId/taskId, parents[], kind, payload, payloadHash, recordedAt`。`parents` 是本设备已观察到的最大操作头集合，用于判断先后与并发；`recordedAt` 用于审计，不当作真实全局先后。

ProjectionIntent 与 Receipt 写实际锚点的 `v2:op:<scopeId>:<opId>`，仍为共享不可变日志。intentId 由 sourceOpId、noteId、载体代数和 phase 派生。单次任务删除会同时失去其自身元数据，不再为独立删除生命周期保留额外控制笔记；重复首篇不可用时只暂停该系列推进，已有后继与本次完成不消失。

不写完整操作数组到同一个键；不直接 PUT 原生 `user_data` 字段；不覆盖其他插件命名空间。派生快照只能是可丢弃缓存，不是新真相源。

### 5.3 键枚举与兼容适配

公开 API 有 `userDataGet/Set`，但没有公开列出全部键的方法。启动发现与归并需要读取笔记的 `user_data`，在一个 `UserDataEnvelopeReader` 中识别当前源码的 `{pluginId: {key: {v,t,d?}}}` 布局，只提取本插件键名，再通过公开 `userDataGet` 读取值并校验哈希。

这是**对存储布局的受控依赖**，不是稳定 API 保证。目标版本必须验证字段可读、合并及删除标记；未知格式暂停写入，不把错误当空日志。v1 的 meta/op/模板笔记仅供清理识别，不迁移、不当作当前数据源，也不重新创建辅助载体。若当前环境无法安全枚举则报告限制，不擅自恢复已被用户取消的额外笔记方案。

### 5.4 本机持久意图与崩溃恢复

使用隐藏的本机插件设置保存有界分片 outbox 与设备 ID；设置只保存本机恢复资料。命令先持久保存 `opId/payload/阶段`，再写同步操作键并读回。写入按控制笔记串行，同一应用内仅一个队列，避免插件自己的 read-modify-write 并发。

操作读回后 UI 才显示“本机已保存”；是否同步由宿主状态表示，不伪造“所有设备已收到”。未完成投影在启动/恢复/同步完成时重放。宿主没有公开全设备确认水位，不能仅因一次 syncComplete 就安全丢弃全部恢复记录；保留最近阶段意图与未解决操作，已完成日志保存在同步控制笔记，压缩/清理需备份和另行验证。

本机 outbox 不是同步替代品；设备在首次同步前损坏，Joplin 尚未上传的数据无法由插件保证恢复。单键写入内部仍是宿主读改写；同步与写入交错的风险不能因“键独立”就宣布消失，必须读回校验、同步后重查及重放。

### 5.5 模板快照、链接与无附件边界

模板只在首篇 userData 中保存标题/Markdown/父版本/哈希，版本不可变。创建时确认初始模板，之后首篇勾选步骤和执行记录不自动改模板；插件“编辑模板”发布新版本，仅影响以后生成的任务。先验证并写快照，再追加选用该版本的规则操作，绝不新建模板笔记。

周期模板拒绝图片嵌入、直接资源附件链接及 data URL，验证必须在创建任务/发布新模板前执行，不能先留下半建系列或静默剥离。允许普通网页链接及 `:/noteId` 资料笔记链接；同语法也能指向资源，需查询对象类型，未知未同步引用提示等待，不能用正则直接判定全部是笔记。生成后只复制链接文本，不复制资料笔记或附件，不保证被删资料仍可打开。

用户在执行笔记中自行添加的附件不受此限制；不删用户附件、不回写到模板。既然模板不承担资源引用，JSON 中存 ID 不提供保活，也不再以额外笔记保活为由恢复旧结构。资料笔记由用户保留，已有原生附件清理规则不变。[S09]

### 5.6 首篇不可用与旧格式清理

404 不等于永久删除。后继仍显示其原生正文与已保存最小状态；用户可完成本次，完成证据写后继自身，显示“已完成、等待生成”，不生成下次。恢复原首篇后按稳定 opId/周期 ID 重试一次，不接管别篇、不重建空模板；永久失去首篇只能明确重新配置系列，不能声称无损恢复。

本轮用户授权不考虑旧数据，不做 v1→v2 迁移。清理功能独立由项目经理实现：列出本插件命名空间的当前键与删除标记键、旧辅助载体及本机 outbox，再按明确范围处理；不得按笔记本名称或正文相似度删除用户笔记，不删除共享资源。当前格式不新增原生标签；所有关联由上述 userData 键识别。清理后不再由旧 outbox 静默复活数据；与仍运行旧插件的其他设备混用仍需提示风险。

## 6. 周期状态机与推进

`resolution`、`consumed` 和 `active` 是三个维度：未完成历史可以存在，但只有逻辑活动周期可以推进。不能用原生 `todo_completed=0` 推断它一定是活动周期。

| 当前状态/操作 | 领域结果 | 原生投影与推进 |
| --- | --- | --- |
| 活动 open → complete | completed，记录完成时刻 | 先保存操作；消费一次并生成后继/结束；B 保留完成笔记，A 推进同一载体 |
| 活动 open → skip | skipped，不计为完成，消费一次 | 清旧提醒；推进一次；B 原笔记保持可访问并标为跳过，默认 `is_todo=0` 且显示状态说明，不伪填完成时间；正文不改 |
| 活动 open → defer | 只变 deferredDate | 必须晚于当前有效计划；不改规则、锚点、周期 ID；相对提醒随延期移动 |
| 活动 open → snooze | 只变 reminderOverride | 不改 scheduledDate/deferredDate/anchor；只重排单个原生提醒 |
| 已推进历史 → reopen | 历史变 open，consumed 仍 true | B 对应历史笔记恢复未完成但不再驱动系列；A 只改历史记录，不退回当前载体 |
| 已消费历史再次 complete/skip | 更新历史结果但不新增推进边 | 不生成第二个后继，不重置当前笔记 |
| 活动结束/结束次数耗尽 | ended | 不生成后继，清提醒；现有历史保留 |
| 规则冲突/载体缺失 | pausedConflict/missingCarrier | 不生成、不开新提醒，显示原因与恢复入口 |

B 跳过转为非待办是必要状态映射的设计默认：原生只有完成/未完成而无“跳过”。标记保存在插件元数据，标题不添加前缀、正文不改，原笔记及链接保留；插件 UI 用元数据状态提示。如撤销跳过则重新转回待办，依然不撤销已消费标志。必须在用户执行跳过前用短说明提示此原生差异。

### 6.1 正常推进流程

1. 校验目标 `occurrenceId` 仍是活动周期，规则无冲突、模板可用、笔记未删除/转换。
2. 持久化并读回 complete/skip 操作；界面进入“推进中”，重复点击沿用同一请求 ID。
3. 归并操作得到消费结果，若已经存在有效 `Advance` 就恢复其投影，不重新计算一份新的下一次。
4. 基于当时规则版本、原始锚点及处理时刻计算下一日期；计算失败/超界则保留已完成结果、暂停推进并显示原因。
5. 持久化不可变 `Advance`，包含后继逻辑 ID、完整计划与模板版本。结束条件满足则记录结束，不创建后继。
6. A 复用原载体并绑定到后继；B 先创建 `todo_due=0` 的新待办，再写绑定，最后安排单个提醒。
7. 读回投影，更新可重建快照，通知 UI。任何一步失败由 outbox 与 `Advance` 恢复，不再应用同一消费。

### 6.2 下一次、漏期和计数

- 按计划基准：在原规则序列中取严格晚于实际处理时刻的第一项，同时晚于当前周期原计划位置。完成或显式跳过均适用。全天按任务日期的自然日比较，今天的同日全天项不再生成。
- 延期后跨过多期：不连续补建，记录略过区间；下一真实周期使用原锚点，不使用延期日作新锚点。
- 按完成基准：使用完成/跳过发生时刻在任务时区的日历日期计算下一个候选，保留系列钟点；若候选仍不晚于处理时刻继续到下一合法项。多选星期以处理时刻之后首个符合间隔周的日子为准。
- 按完成基准也可配农历：先将处理日期转换为农历序列位置，再按规则步进；年/月选择器依然保留，不擅自改成公历间隔。
- 次数限制在同一消费边上计一次，撤销后再次完成不增加。修改次数小于等于已消费数时，保存预览明确“无剩余次数”，不偷偷重置。
- 截止日期、有限次数、无法转换的日期边界均在产生 `Advance` 前检查。

### 6.3 规则编辑与模式切换

编辑提交时携带基于的规则版本。无并发时新版本作用于当前尚未消费周期及未来，保留 cycle ID；更新计划、提醒并保留已存在正文。结束/停止不删除历史。正文修改始终是原笔记内容修改，不反向改模板。

模式选择保存为 `modeForNext`：A→B 下一次创建独立模板任务；B→A 为保留当前 B 历史，下一次从当时系列模板新建一个 A 起始载体，再从该载体持续复用。已生成的其他历史不改，切换本身不立即复制或合并；模式边界每次只新建一次。

## 7. 多端归并、冲突与最终收敛

### 7.1 保证范围

本地串行队列只防止本设备重复点击。同步不提供跨端锁、CAS、全局唯一约束或事务，不能保证双端离线时从未产生重复物理笔记、重复投影或已投递通知。

设计目标是在相关操作与笔记最终同步可见、相关设备再次运行插件并完成归并后：同一逻辑周期只有一个活动身份、一个规范后继；重复物理候选可辨识、可恢复，未编辑重复可收敛为非活动恢复资料，已编辑分支必须保留；相同操作重放不额外推进。**这是条件性最终收敛目标，尚未测得，不等同于需求 A14 已通过。**

### 7.2 合并算子

首先按 `opId` 做集合并集，同 ID 内容哈希必须一致；不同内容属于损坏/冲突，停止自动写。校验因果 DAG，依赖缺失先缓冲，拒绝循环，未知操作保留并将系列置只读。**存在缺父操作、缺模板/载体依赖或无法判读的控制信息时，整系列副作用暂停，包括清 todo_due、转换 is_todo、写绑定和新建笔记；不能用残缺快照做“清理”。** 只显示最近完整快照及等待状态，依赖齐全后重新归并。

唯一例外是 Advance 明确声明、尚未执行的**本机创建步骤**：父操作与模板全部完整、本机持久 outbox 能证明对应创建意图时，待创建 candidate 不存在是可恢复的预期空缺，不属于未知同步依赖，可按 7.3 恢复该 POST。其他设备的候选 404、已绑定载体 404 和任何无法证明的空缺只等待/暂停，不自动重建。

派生规则：

- 因果上后发生的同字段修改覆盖其明确观察到的前值。并发优先级/置顶等简单字段以稳定 `opId` 字典序确定显示值，保留另一值供审计，不依赖设备墙钟。
- `ReviseSeries` 的因果最大头若多于一个，保留全部规则/模板分支并暂停新推进。`ResolveSeriesConflict` 必须引用全部已知冲突头；后来才同步到的新分支会再次显示冲突，不能假称已永久解决。
- 并发完成同一周期：保留两条操作，按稳定 `opId` 选规范消费依据；只产生一个逻辑后继。不同完成时刻都保留，选中依据决定按完成基准的计算。
- 并发 complete/skip：默认完成作为展示结果，跳过操作保留；逻辑周期只消费一次。若由此产生的两个 `Advance` 日期/模板/规则不一致，暂停后继投影而非悄悄重排已编辑任务。
- reopen 必须引用已观察到的完成/跳过，不能自动撤销未见过的并发结果。已消费集合是只增集合，不因 reopen 缩小。
- 删除/转换与完成/跳过并发：删除或脱管意图阻止继续自动创建，暂停并列出两端操作；不以完成为由把用户已删笔记重建。明确恢复后才继续。
- 完成与延期/稍后提醒并发：消费后的旧周期不再排提醒，保留延期请求记录；后继不继承旧周期 snooze。历史再次打开也不自动恢复过去的提醒。
- 分离字段操作可交换；规则、模式、模板作为整体版本处理，不对互不兼容的局部补丁做猜测合并。

集合归并要求幂等、交换、结合；派生结果在相同完整输入集合下确定。Joplin userData 的时间戳合并是传输层行为，本设计集合语义建立在不可变唯一键不被删除覆盖之上，不替代对实际同步的故障测试。

### 7.3 物理候选与创建幂等

`Advance` 内预先持久化 candidateNoteId，由 `seriesId + occurrenceId + creatingOpId + namespace` 哈希截取 32 位十六进制；该值只固定同一次创建尝试，不是跨端互斥。当前 notes 路由源码接受请求中的 `id`，但未据此宣称 POST 是 upsert。[S10]

创建顺序：GET 该 ID → 若不存在则 POST → 成功后 GET 校验 → 写 meta/Bind。POST 报存在、超时或结果不明时先 GET 比对，不盲目覆盖。若已有笔记身份/哈希不匹配，判冲突并停止。若目标版本不支持 caller ID，W01 阻止此流程进入编码，改用持久创建意图+结果发现方案重新评审。

两端不同创建操作会得到不同候选 ID：相同内容且未编辑时，按稳定 creatingOpId 选规范候选，其余标为重复恢复候选，清 `todo_due`；在确认未编辑、身份完整且读回通过后可转为 `is_todo=0`，不删除正文或资源。已编辑或被原生完成的候选不自动删、合并正文或改写完成结果；列出差异并暂停相关后继推进，选择哪个保留为活动后再清其他提醒。面板只把规范候选计为一个逻辑任务，但仍展示冲突入口。

自动清理是多步投影，期间仍可能暂存多个原生待办。两端独立已触发的通知无法撤销过去事实；下一轮归并只能尽力取消未来重复通知。不得将“插件 UI 隐藏重复”当作所有原生重复已修复。

### 7.4 同步和恢复触发

启动、用户刷新、同步完成、笔记选择/当前笔记变化、已知任务操作后启动增量归并。公开 onNoteChange 主要针对当前笔记，不假定它是全库变更流；使用 Data API events 游标增量扫描并处理分页，游标过期、事件缺失或宿主版本不支持时执行分页全量索引。后台/前台恢复事件能力待验证，至少在面板 ready/打开时校验时间与数据；不设置秒级全库轮询。

同步传输可乱序：控制操作已到而模板/候选未到时进入“等待同步”，不立即重建；只有用户明确恢复或本机 outbox 证明这是自己的未完成创建，才执行创建。404、权限失败、未解密、资源未下载、回收站与永久删除分别记录。恢复任务带限次重试与退避，超过阈值显示错误，不无限写回循环。

同一原生根笔记并发建立多个 seriesId 时按 rootNoteId 发现重叠绑定，暂停并保留两个定义，不让两个系列各自推进。创建恢复的自动 POST 权限只来自本机持久 outbox 对应的已验证创建意图；别的设备只看到 Advance 与 404 必须等待同步，不能代替原创建端补 POST。

## 8. 日期、时区与农历实现

### 8.1 固定任务时区

创建定时任务保存 IANA zone、当地年月日钟点及解析后的 instant/offset。展示可换算到设备时区，但不改变存储的事件时刻。设备未改变时区就不会因 GPS/IP 改显示。重复每次由规则的当地钟点重算，不以毫秒加 24 小时代替日历日。

`TimeZonePort` 使用 `@js-temporal/polyfill`，区分 `PlainDate/PlainDateTime/ZonedDateTime/Instant`；启动检查 `Asia/Shanghai`、当前设备 zone 和数据中出现的 zone。无效 zone 不回退为 UTC 或设备时区，而是阻止涉及计算的写入，显示原值与错误。不同设备时区数据库可能不同，影响远期 instant；已物化周期保留已确认 instant，不因库更新静默移动，未来预计结果带计算环境版本用于诊断。不假定 polyfill 自带独立、固定版本的完整 tzdb。

### 8.2 夏令时默认值

- 缺失钟点：按偏移缺口向后平移，例如纽约春季不存在的 02:30 取 03:30；保存原规则 02:30，之后正常日期仍是 02:30。
- 重复钟点：采用与 Temporal compatible 相同的明确产品策略，通过候选 offset 解析（重叠选较早 instant、缺口向后平移），只执行一次；不能依赖运行库隐含默认值。
- 日期整日被时区变更跳过、无法稳定解析等异常：暂停该期计算并提示，不猜另一天。
- 定时任务即使在设备新时区显示到前/后一天，计划 instant 不变，并标示任务原时区；这与全天日期不漂移不同。

以 `disambiguation: "reject"` 辅助检测异常，再按上述明确策略解析；原始钟点、有效钟点、偏移与调整原因要可观测，适配器锁版本并测试。[S11][S12]

### 8.3 全天日期与视图区间

全天只保存 date 与 taskZone，显示在相同日期格，不经 UTC 导致日期偏移；逾期时刻为其 taskZone 的下一自然日开始。设备本地“今日”取本地日期字符串，七天为七个自然日期，不能算 7×24 小时。

查询时：定时任务按 instant 映射设备本地日期；全天按日期字面值落格。因跨区出现“日期看起来昨天但原时区尚未结束”时，不通过设备午夜错误标为逾期，详情说明任务时区。日历标题、提醒时区与逾期判定必须使用同一接口输出，禁止 UI 自行 Date.parse。

### 8.4 农历封装

`LunarCalendarPort` 仅输入/输出年月日及闰月标记，不接收宿主本地 Date，避免设备时区污染。公农历日期表语义采用 Asia/Shanghai；转换得到的公历 date 再结合任务固定 zone 和当地钟点解析提醒 instant。也就是说，农历规则日期一致，提醒钟点仍在任务时区执行，UI 同时标明两者，不把“中国农历某日”误当上海午夜的绝对事件。

- 普通月年度规则不在同名闰月额外执行。
- 指定闰月年度规则：有该闰月用闰月，没有则用同名普通月；保留原闰月属性，不能下次永久变成普通月规则。
- 每月农历步进把闰月作为独立月份计数，间隔从原锚点计算。
- 三十遇小月取该月末；除夕取下一农历年首日前一日，不能固定腊月三十。
- 目标覆盖公历 1901—2099 内可转换日期；两端往返、边界与 independent table 对照通过后才声明支持。靠边界的下一周期算不出时可完成当前，但系列暂停，不写错误下一日期。

当前采用 Intl Chinese calendar，原 lunar-typescript 为选型研究。[S13] 独立对照采用香港天文台公农历对照资料，涵盖 1901—2100；其资料本身也说明远期计算存在临界午夜日期差异，应记录差异与采取的历表版本，不能把两个库互相验证当独立真值。[S14]

## 9. 原生提醒、字段投影与外部修改

### 9.1 单字段职责

| 插件字段 | 用途 | 原生字段 |
| --- | --- | --- |
| `scheduledDate` | 原计划与视图日期，延期不改原值 | 存插件元数据，不要求与 todo_due 相同 |
| `deferredDate` | 本周期有效计划日期 | 存元数据，改变视图及逾期，不改系列锚点 |
| `reminderPolicy` | `off` 或 `atEffectiveDue`；全天开启时用任务时区 09:00 | 解析为单个提醒 instant |
| `reminderOverride` | 插件内稍后提醒指定的新 instant | 覆盖当前唯一提醒，不追加第二个 |
| `todo_due` | 宿主提醒投影 | 需要提醒时为 reminder instant；无提醒/完成/跳过/停止时为 0 |
| `todo_completed` | 原生完成状态 | 未完成 0；完成为实际完成 Unix 毫秒；不是布尔 1 |

新建全天及定时任务默认提醒关闭；UI 明确展示“无提醒”，不能静默写午夜。用户显式开启时，定时任务采用有效计划时刻，全天默认 09:00 且可编辑该单个提醒钟点。稍后提醒只维护同一个原生字段，给出预设延迟与具体新提醒时间，必须严格晚于当前时刻。延期只平移与有效计划绑定的提醒；已有 snooze 默认保留其绝对时刻，保存前提示冲突并允许重新选择，不静默取消。

**原生界面差异：** 无提醒的有日期任务原生 `todo_due=0`，宿主可能显示无闹钟/无原生日期；稍后提醒后宿主显示提醒时刻，而插件仍显示原任务计划。这是字段语义的必然后果，插件详情明确区分“计划”和“提醒”。不为消除差异另造系统通知服务。

### 9.2 外部编辑矩阵

| 观察到的原生变化 | 处理 |
| --- | --- |
| 未纳入元数据的原生待办，todo_due 非零 | 保留原值，按定时任务与原生提醒显示；不重新选择时区到上海 |
| 已管理笔记标题/正文变化 | 原样显示，不更新系列模板，不扫描内部复选框 |
| 完成状态改变 | 产生 ObserveNative + complete/reopen 语义；以已绑定周期判断当前/历史，不只看 noteId |
| 已管理 todo_due 改为新非零值 | 默认视为用户在原生闹钟入口调整提醒，不改变系列规则、原计划或延期；插件明确显示新提醒时刻 |
| 已管理 todo_due 改为 0 | 关闭当前提醒，不清空计划日期或锚点 |
| 原生改日期且用户意图是改计划 | 插件提供“采用为计划日期”明确入口；普通任务可改计划，系列只能编辑系列或走延期；不猜测意图 |
| 转换成普通笔记 | 先检查共享 ProjectionIntent/Receipt；与 B 跳过/重复候选恢复投影匹配则是插件写入，不脱管；否则记外部脱管/暂停，不自动再转回待办 |
| 删除/回收站 | 停止该载体的推进，保留元数据供显式恢复，不创建替代笔记 |
| 移动笔记本/修改标签 | 更新显示；活动载体的来源变化成为未来新建默认来源，不修改 B 既有历史位置 |

这样满足“原生日期修改相互反映”，但不把原生闹钟修改悄悄升级为系列规则修改。若发现 requirement 对原生日期含义有不同预期，再用实际示例讨论；不让用户选择 API 字段实现。

### 9.3 自身写入、恢复与循环抑制

每次投影先将 ProjectionIntent 写入控制笔记独立操作键并读回，再持久更新本机阶段、重新读取 note。实际值既不是 before 也不是 after 时先记录外部修改并重新归并，不直接重试覆盖。写成功后读回；一致则追加 ProjectionReceipt。其他设备读取共享 intent/receipt 与载体代数后才能识别自身回声，不能仅依靠本机内存 suppress 标志。

API 不提供原子 compare-and-set：读后写前仍可能被原生编辑或同步抢先，故指纹只减小风险，不证明无丢写。保存前不提交正文，只 PUT 必要字段；投影后不匹配时保留证据、暂停并提示，不反复把用户值“修正”回去。

A 推进同一笔记时的原生 `completed → open + 新 due` 必须带新周期绑定与 receipt，避免下一次扫描把它误认为用户撤销。若另一设备读到的 native tuple 与同 noteId 旧 carrierGeneration 的 intent/receipt 匹配，判作旧投影/乱序回声，不把旧完成推进当前周期；等待依赖同步后恢复新代投影。没有 Receipt 但原生值已等于已持久 Intent.after 的崩溃窗口，可核验后补 Receipt。任一依赖缺失时按 7.2 暂停，不清字段。旧周期历史状态不能从当前载体字段重新反推。

### 9.4 投递能力边界

插件不负责系统通知投递成功保证。桌面在托盘仍运行可以有计时器，彻底退出不会继续计算；Android 已预排原生通知可能继续由系统投递，但挂起时插件不保证响应事件或生成下一期。

不以 onNoteAlarmTrigger 作为唯一真相：启动与面板打开时检查 overdue reminder 状态，不自动重发已过期提醒造成通知风暴。权限、锁屏、强停、重启与通知已投递后撤销需单独真机测试。任务数据与单个原生提醒跨端同步后，各宿主可能分别投递，不承诺全设备仅一次通知。

## 10. 未来预计周期、查询与性能

### 10.1 预计计算接口

`previewOccurrences(seriesSnapshot, visibleDateRange, deviceZone, limit, cancellationToken)` 是只读函数，输出 `candidateSlotKey, date/instant, sourceRevision, provisional, assumption`，预计项不冒用 OccurrenceId。不能写 metadata、Advance、原生笔记或提醒；切换月份/年份不会触发创建待办。

- 以可见区间为界：月视图含日历网格前后补齐日期；年视图按年聚合日期数量，点击日再取明细。
- 从规则锚点直接定位区间附近的日/周/月/年，不能从 1901 年逐天跑到当前年份。
- 每个实际周期保存 `originSlotKey`，用它替换预计槽位，不按延期后的日期去重。延期项只在有效日期显示一个实际任务，原计划位置至多显示不计数的“已延期”说明。
- 编辑规则保留当前 OccurrenceId，将旧 originSlotKey 和新规则映射到的当前槽位加入 suppressedSlotKeys；当前任务只改计划投影，不重新生成。未来预计只从新规则当前映射位置之后展开。若新规则无法映射原计划，保存前明确当前新计划槽位并记录映射，不能以 revision 变化为由让旧活动周期和新预计项各算一次。已消费旧版本位置不在新版本再次物化。
- 实际完成产生 Advance 后，把选中的 candidateSlotKey 写入后继 originSlotKey；当前未完成时可有多个预计槽位，但它们不预先建立后继 OccurrenceId 链，也不各自触发创建。
- 当期未完成仍显示后续预计日程。按计划基准的未来日期依规则确定，但实际创建仍需消费；按完成基准只能假设各期按预计时刻处理，明确标记“按如期完成估算”，完成后重算，不能称确定承诺。
- 对预计项仅提供查看规则/模板入口，不打开不存在的原生笔记、不提前完成。
- 规则冲突显示冲突标记和各分支可辨识预览，不叠加成正常重复任务；无法计算区域显示原因，不冒充“没有任务”。

### 10.2 缓存与预算

查询缓存键包含系列规则版本、当前周期/消费版本、可见范围、任务与设备时区、日历适配器版本；失效时丢弃重算。模板正文修改通常不影响日期缓存，但规则操作版本仍更新摘要。

使用分块运算并让出事件循环，切换视图时取消旧查询，保留 requestId 防止旧结果覆盖。设计初始工作预算：每片约 8 ms、每系列每查询最多 500 个预览、单视图总计 20,000 个；达到预算显示进度/分批加载，不能静默丢日期。年视图优先返回每日数量，再按点击加载标题。预算为实现参数，不是已测性能保证；基准覆盖超预算数据，并按测试调整。

只对可访问原生待办建立轻量索引；模板正文按需读取，不把全部附件二进制加载进内存。不使用 Worker 作为必要条件；若以后采用必须先证明移动资源加载与通信可用，不在纯预览算法中依赖它。

### 10.3 原生无日期待办的可发现性修复

#### 问题定位与边界

已检查当前代码：`TaskApplication.collectTasks()` 收集未纳入插件元数据的原生待办，`importedTask()` 把 `todo_due=0` 映射为 `Schedule.kind="none"`；`projectView()` 遇到该类型直接跳过。因此“已读到任务”与“面板能看见任务”之间存在投影缺口，不能只增加刷新次数或重启来解释此类不显示。

需求仍以 v0.4 为准，不修改“无日期任务不自动归入今日”，也不把暂缓的“无日期独立视图”扩展为已选功能。本修复是在现有四视图中增加共同辅助区，提供原生任务可发现性和设置日期入口；它不属于任何日期格、没有虚构的执行日期。

#### 数据与显示契约

- 保持 `Task.schedule={kind:"none"}`。实现复用快照已有 `tasks: Task[]`，由 `UnscheduledTasks` 独立筛选渲染，不另存一份列表，也不将无日期任务强行转换为要求日期的 `PreviewItem`。
- 四视图面板的日期内容之后显示“未安排日期（N）”辅助区；无日期项不进入今日/七天范围、月/年日期格，不参与日期任务计数、逾期判断或预计周期计算。首次有任务时默认可见，折叠只是布局操作，不能当作任务隐藏或状态修改。
- 辅助区只展示可访问、未完成的实际原生待办：`is_todo=1`，无插件有效计划或原生 `todo_due=0`，且不是删除、冲突、加密未解锁或插件数据载体。若插件元数据已有计划，必须采用插件计划，不因提醒关闭导致原生 `todo_due=0` 而误放入此区。
- 单个原生 note ID 只能出现在日期区或无日期区之一；受系列当前载体/历史状态规则约束，不能把已经绑定的历史笔记作为普通新任务再导入。普通笔记和正文复选框仍不展示为任务。
- 标题、完成、打开笔记与基础编辑入口沿用现有任务动作。点击设置日期后走现有单任务编辑/管理入口，保存成功再从辅助区移动至正确日期；只看列表不创建系列/控制记录，不转换笔记类型。
- 空状态区分“当前日期范围没有任务”和“没有任何未完成任务”。日期区为空但无日期区有项目时，不能显示暗示整个任务库为空的“没有任务”。读取失败继续沿用明确错误状态，不伪装无日期数量为零。

#### 原生新增与刷新补偿

新建、选中笔记变化、宿主笔记变更、同步完成及用户主动刷新应触发已有受控刷新协调器。公开当前笔记事件不能被假设为可靠的全库创建事件；面板打开/ready 与手动刷新必须能够重新发现原生待办。刷新与只读发现不写 `todo_due`、`todo_completed` 或正文，不为让项目进入日期视图自动分配今日、午夜或提醒。

#### 修复验证要求

1. 原生新建未完成待办、`todo_due=0`、无插件元数据：启动扫描和原生新增后的刷新均能在辅助区显示一次，原生字段保持不变。
2. 计划在今日且关闭提醒的已管理任务：仍在今日，不因为 `todo_due=0` 重复出现在无日期区。
3. 给无日期任务设置日期后进入对应日期区；清除普通任务日期后回到辅助区；重复任务不允许清空有效基准。
4. 月/年/七天切换、逾期开关及设备时区变化不为无日期任务制造日期或逾期状态；完成后从辅助区消失。
5. 普通笔记、内部复选框、系统控制/模板笔记、已完成、回收站及冲突载体不混入；分页发现与手动刷新不产生重复项。
6. UI 测试覆盖辅助区计数、空状态与动作入口；宿主验证覆盖真正的原生新建和可用事件。静态分析能定位过滤缺口，但不等同于 Joplin 真机修复已通过。

## 11. 面板、交互与跨端适配

界面流程以 [界面与交互设计](界面与交互设计.md) 为准，规划目录见 [代码结构](代码结构.md)。React 组件不得直接访问 Joplin API。创建稳定 panel ID，桌面验证新布局右侧、保留用户布局；Android 采用宿主标签面板，不承诺永久侧栏。不能虚构强制布局 API，不能反复抢焦点。

偏好仅本机保存：`startupMode(fixed/restore), defaultView, lastView, overdueToday, overdueSeven, panelPreferences`。固定模式优先于 lastView；启动月/年定位今日，隐藏重开保留浏览位置。午夜、面板 ready、恢复交互重新校验日期和 zone。

### 11.1 消息协议

面板先发 `ready(protocolVersion, requestId)`，插件回复完整 `snapshot(snapshotVersion)`；主动推送使用同一 onMessage 路由。命令带 `requestId, expectedSnapshotVersion, targetOccurrenceId, payload`，回复 `accepted/saved/conflict/error`。插件只在保存后报告成功；不把 fire-and-forget 当可靠交付。

视图丢失或重载后重新 ready，拿全量最新快照；旧 requestId 重复命令返回原结果，旧 snapshot 的危险操作要求刷新。标题、正文摘要与模板内容采用安全文本/受控 Markdown 渲染，不拼接任意可执行 HTML，不允许来自笔记的脚本。

### 11.2 C11 命令范围

命令/快捷键/上下文菜单与手机可见菜单按界面设计实现；仅 Joplin 应用内，不添加系统全局快捷键或通知动作。危险命令必须带周期 ID 和请求去重，不能因重复按键多推进。

### 11.3 日期导航与禁用状态修复

本次问题为今日/七天的左右箭头被明确设置 `disabled`，同时通用 `button:disabled` 样式使用 `cursor: wait`，悬停表现为等待光标。禁用本身不代表正在请求，也不是任务加载卡住；不能仅增加重试或加载动画处理。

- **今日/未来七天：** 分别查询今天、今天至 T+6；日期锚点随设备本地跨日重新计算，不保存一个能把这两个智能视图移到过去/未来的游标。不渲染左右箭头，不保留可聚焦空壳或“正在等待”的禁用按钮。需要浏览其他日期时通过月/年视图。
- **月视图：** 显示上一月/下一月按钮，按自然月切换；**年视图：** 显示上一年/下一年按钮，按自然年切换。按钮提供明确的可访问名称，不依赖箭头符号猜测。月/年可通过“今天”定位当前月/年。
- **状态样式：** 普通禁用状态使用 `not-allowed` 等明确不可操作样式；仅真实的异步处理中才显示局部加载状态，且与错误/禁用状态区分。不得让全局禁用选择器把任何禁用按钮统一显示为等待光标。
- **数据保护：** 日历前后导航只更新浏览范围，不修改任何任务计划、提醒、系列锚点或原生笔记。切回今日/七天重新锚定今天；月/年浏览位置记忆仍遵守既有启动与隐藏重开策略。

验收覆盖：今日/七天不存在前后导航控件；月/年按钮能够正确跨月、跨年且标签正确；禁用按钮不出现等待光标；视图切换/跨日后智能范围准确；前后浏览不产生任务写入。测试结果另记入测试记录，本节不代替实际验证。

### 11.4 面板滚动与模态背景锁

年视图和长任务列表可能超过宿主插件面板可视高度。仅依赖 `.app` 的内容高度，未明确面板文档的高度与滚动容器，会出现下方内容超出却无法滚动的问题。修复采用明确的单一主滚动容器，不裁剪任务或缩小年历来掩盖溢出。

**对上一版设计的纠正：** 用户确认 0.1.3 仍无法滚动后，已只读检查本机 Joplin 3.7.21 的 app.asar。原设计误把插件内容视为 `body` 的直接子节点，漏掉宿主包裹层；仅验证独立页面中 `body > #root` 的滚动不足以证明真实插件面板可滚动。以下宿主语义替换此前不完整的高度链建议。

#### 已核验的宿主 DOM 与 setHtml 语义

本机资料来自 [Joplin app.asar](/Applications/Joplin.app/Contents/Resources/app.asar)，只读解析其中的源码与 `package.json`，未修改应用。版本为 **3.7.21**。实际桌面插件面板由 `services/plugins/UserWebview.tsx` 加载 `UserWebviewIndex.html/js`，不是正文预览的 `gui/note-viewer/index.html`。

```text
插件面板 iframe（宿主为其分配固定可视高度）
└─ html                       宿主默认 overflow:hidden
   └─ body
      └─ #joplin-plugin-content-root   宿主脚本创建
         └─ #joplin-plugin-content     宿主设置 display:flex; flex-direction:column
            └─ #root                  本插件 setHtml 片段创建
               └─ .app                React 内容
```

- `UserWebviewIndex.js` 创建两个包裹 div，`setHtml` 实际执行 `contentElement.innerHTML = args.html`。因此传入完整 `<!doctype html><html><head><body>…` 不会替换宿主 document，也不会让 #root 自动成为 body 的直接子节点。应只传本插件根节点片段，例如 `<div id="root"></div>`；资源继续用 addScript 加载。
- `UserWebviewIndex.html` 的宿主样式使 html 不滚动、content 使用纵向 flex，但未给这两个包装 div 声明确定高度。漏过这些祖先时，root 的百分比高度不能形成预期的视口约束，内容会把自动高度容器撑开，而外层 html 又不能滚动。
- `gui/MainLayoutPane.tsx` 调用 `<UserWebview fitToContent={false}>`；iframe 的 `.plugin-user-webview` 样式为 `height:100%`。面板已有宿主视口高度，不应通过对话框 fitToContent 机制或修改宿主应用文件补救。
- 以上是本机版本源码证据，不是浏览器实际滚动测量，也不证明 Android DOM 相同。相应 GitHub 原始路径本轮访问返回 cache miss，未把无法取得的在线内容冒充已核验资料；本地版本及可重现文件指纹见 [S16]。

#### 高度与滚动归属

- `html`、`body`、`#joplin-plugin-content-root`、`#joplin-plugin-content` 均补齐确定的 `height:100%` 与 `min-height:0`，外层不承担页面滚动；必要时设置 `min-width:0`。`#joplin-plugin-content` 保持纵向 flex，`#root` 以明确高度或 `flex:1 1 0`、`min-height:0` 限定在可用视口，并独立 `overflow-y:auto`。不能再只设置 html/body/root 三者。
- 对宿主包裹层的选择器是版本相关 DOM 适配，不能当成公开 API 永久保证。目标版本需要检查实际祖先链；若包装层变更或 Android 使用不同结构，应保留 #root 的视口滚动约束并验证相应布局，不修改用户的原生应用文件。
- `.app` 按内容自然高度布局，不给年历、列表或页脚设置会截断内容的固定高度。滚动范围必须覆盖最后一个月、最后一个任务、未安排日期区和页脚；不依赖 body 的 scrollHeight 充当 root 的滚动依据。
- 保留窄屏断行与网格收缩能力，不因简单 `overflow-x:hidden` 让按钮、标题或编辑入口不可达。年历仍按响应式网格显示，长中文标题/连续长字符串不能撑宽面板。
- 鼠标滚轮、触控板、触摸、键盘滚动及焦点移动均作用于实际可滚动容器；不通过全局 `preventDefault` 拦截滚动。主区可用 overscroll 控制防止滚动串到宿主，但不能阻止自身到达内容末端。

#### 模态抽屉

- 延续现有 `position:fixed; inset:0` 遮罩和独立 `overflow-y:auto` 抽屉，抽屉高度限制在当前视口。不要给其祖先增加会改变 fixed 定位包含块的 transform/filter/contain；本修复不要求必须引入 portal。
- 主滚动容器变为 `#root` 后，打开抽屉必须锁定 root 的纵向滚动，保存原内联 overflow 值与滚动位置。关闭、表单卸载和异常清理时恢复原值及位置，避免关闭后仍不能滚动或跳回顶部；只设置 `body.style.overflow="hidden"` 不足以锁住新的主容器。
- 锁主区不能锁抽屉自身。长表单、系列历史和模板正文仍可独立滚至末尾；抽屉可设置 overscroll containment 避免触摸/滚轮穿透到背景。焦点陷阱与关闭后焦点恢复沿用既有可访问性约束，不因锁滚动破坏键盘操作。
- 若后续改用 portal，优先将独立 `#overlay-root` 放在 body 下、与主 `#root` 并列，使其不依赖主内容滚动位置；不得把弹窗挂到会随内容移动或被不当裁剪的容器。两条路径选一种即可，不能同时创建重复遮罩/抽屉。

#### 验证边界

实际布局验证至少覆盖低高度窄面板的十二个月年历、长任务列表、无日期辅助区、长表单和历史记录：能触达末项；滚动条属于 root；打开抽屉后背景不动而抽屉可滚；关闭后背景位置恢复且继续可滚。切换月/年、窗口缩放与手机软键盘出现时，不出现被截断的保存/关闭入口。

回归页面必须复刻上述两个宿主 wrapper、content 的 flex 样式与 html overflow:hidden，并通过与宿主相同的 innerHTML 方式插入片段，不能再用省略包装层的独立页面代替。至少断言 root.clientHeight 受 iframe 视口约束、长内容时 scrollHeight 大于 clientHeight、实际滚动后 scrollTop 增加且能到达末项；还要测抽屉锁恢复。DOM 字符串/CSS 正则或模拟对象测试只能检验配置，不能证明浏览器布局可滚动。真实 Joplin 及 Android 验证仍分别记录，未执行就列待验证。

### 11.5 可扩展多语言设计

用户明确要求将语言内容放入方便后续扩展的语言文件。本项新增界面多语言能力，既有任务范围与业务规则不变；首次提供 `zh-CN` 与 `en`，不安装额外 i18n 框架或在线翻译服务。

#### 文件与注册契约

| 规划文件 | 职责 |
| --- | --- |
| `src/i18n/locales/zh-CN.json` | 中文基准词典，平铺语义 key → string；定义完整键集合 |
| `src/i18n/locales/en.json` | 英文词典，保持相同语义键与命名占位符 |
| `src/i18n/registry.ts` | 显式导入与注册 `id/nativeName/dictionary`，避免运行时扫描文件系统或从 CDN 加载 |
| `src/i18n/index.ts` | locale 解析、逐键回退、插值、缺键诊断及翻译接口；可在插件和面板两端使用 |

词典键采用稳定语义命名，例如 `views.today`、`tasks.undatedCount`、`actions.complete`、`errors.readFailed`；不能以整段中文原文作唯一标识，不把业务 ID/用户内容当作翻译键。JSON 值为纯文本，不包含可执行代码或要求 HTML 注入的标记。

新增语言流程：新增 JSON → 注册语言 ID 与语言自称 → 检查键/占位符 → 构建和验证；不要求修改每个组件。当前设置允许值为 `auto | zh-CN | en`，未来由注册表导出的可选语言扩展，不在组件内另维护第二份语言列表。

#### 翻译函数与插值

建议公共契约为 `resolveLanguage(preference, systemLocales): LocaleId` 与 `t(key, params?: Record<string, string | number>): string`，调用方可通过固定 locale 的 translator 或共享 locale context 使用；核心函数不直接读取 DOM、系统时间或持久化。

使用命名插值 `{count}`、`{date}`、`{title}`，例如 `tasks.undatedCount` 对应“未安排日期（{count}）”/“Unscheduled ({count})”。参数视为普通文本，交给 React 安全渲染；不 eval、不通过参数生成 HTML。同一个键的所有语言必须具有相同占位符集合，测试检查漏参、额外参数和不可解析占位符；缺参不得静默输出 `undefined`。数值/日期按有效 locale 格式化后插入，避免拼接碎句导致英文语序不可调整。

查找顺序为“当前语言有效字符串 → 中文基准有效字符串 → 可诊断的键名”。缺译只回退该键，不把整个界面重置为中文；未知键不返回空白或使组件崩溃，开发/测试记录缺键。注册表损坏/不支持的语言设置回退中文并保留可解释状态。

#### 本机语言偏好与运行时切换

- `ViewPreferences.language` 保存 `auto | zh-CN | en`，默认 `auto`，仅本机持久化；旧偏好无此字段时兼容为 auto，不触发任务 schema 迁移。
- auto 使用明确传入的系统 locale 优先序列，例如面板 `navigator.languages`，必要时以运行时 `Intl` locale 补偿；解析统一规范大小写与语言子标签。`en-*` 匹配 en，`zh-*` 匹配当前唯一中文包 zh-CN，未支持语言回退 zh-CN，不声称提供繁体翻译。语言来源必须可测试，不因任务时区推断语言。
- 用户手选优先于系统；切回 auto 重新解析。打开设置、语言切换及系统 languagechange 后更新有效 locale 和 UI 翻译；不要求重启插件，不因 language 变化丢失当前视图日期、滚动位置、表单输入或选中任务。
- 切换语言只保存本机偏好、更新翻译 context 与无业务副作用的显示快照；不写原生标题/正文、系列 op、模板、日期、时区或 `todo_due`。不能为显示另一语言而重新创建任务或推进周期。
- 日期/星期/月名、数量和相对说明使用选定显示语言；领域数据与农历计算继续使用稳定的 ISO/数值输入。农历显示可翻译标识和月份说明，但不得将显示语言带入重复规则解析或把语言切换当作修改历法。

#### 翻译覆盖与用户内容保护

所有自有界面文字均经词典：四视图、导航、按钮、菜单、设置、表单标签/提示/校验、优先级、重复/农历摘要、历史状态、预计周期假设、未安排日期区、空/加载/失败/冲突提示、确认文案及无障碍名称。宿主命令/设置注册的标签也使用同一词典；其运行时重注册能力按宿主接口实际验证，不把静态宿主注册文本遗漏为英文硬编码。

服务/领域错误优先输出稳定 `code + params`，面板根据 code 翻译；诊断码、操作 ID 与技术 detail 可供展开查看。已存在错误需用显式错误码/兼容适配覆盖，不能通过扫描所有字符串并替换中文片段来“翻译”错误。未知异常显示本地化通用提示并保留原始技术 detail，不假装已成功翻译所有第三方原文。

**用户任务标题、正文、模板正文、标签和笔记本名称保持原样。** 它们可以作为安全插值参数展示，但不能被机器翻译、替换、改写，不能以语言切换触发任何数据迁移。

#### 验证要求

1. 中文基准键齐全、英文键/命名占位符一致；增加注册语言即可加载，缺译逐键回退中文，未知键和缺参有诊断。
2. auto 的 en-US/en-GB/zh-CN/zh-TW/未支持 locale 与手选覆盖均有确定结果；旧偏好恢复、无效设置和系统语言变化均有测试。
3. 两语言覆盖主视图、表单、错误、空状态、菜单和 aria 文本；长英文/中文窄屏不被裁剪。字典检查不能替代组件实际展示验证。
4. 运行时切换保留未保存输入、日期和滚动状态；Joplin 数据写入 spy 证明没有任务/模板/提醒字段写入。用户内容逐字一致。
5. 错误码到翻译键映射、未知错误回退与 detail 保留可验证；不使用任务标题是否像翻译键来决定改写内容。

### 11.6 已有普通待办开启重复：规则初值与可见保存反馈

用户明确场景为“给已有普通待办开启重复”。本次只读审查发现可复现的静态链路，不把所有保存故障一概归因于宿主或网络，也不修改“重复任务必须有基准日期”的产品约束。

#### 有依据的问题

1. 已有无日期待办打开 TaskForm 时，date 正确为空；但旧 `defaultRule(date)` 对空字符串切片后 Number 转换，得到隐藏的 `month=0, monthDay=0`。用户后来选择任务日期并不会自动更新已初始化的 rule 状态。
2. `validateRule()` 即使规则为 daily/weekly，也会检查存在的 month/monthDay，因此隐藏零值在服务端被拒绝。如果切为 monthly/yearly，零值进入 `min=1` 的 number 控件，原生 HTML 约束可能在 onSubmit 前直接阻止提交。
3. `App.run()` 捕获的服务错误原先只在背景主界面显示，抽屉仍打开，局部表单没有该错误。用户无法看到失败原因，会认为保存按钮无反应。业务规则错误和原生约束拦截应分别有可见反馈。
4. RuleFields 仅使用对象展开补丁，切换频率/日期选择器会留下不再适用的参数；全部取消星期会得到 `weekdays=[]`，而领域校验不接受空数组。显示 fallback（如 `nth ?? 1`）不能代替提交数据的真实合法默认值。
5. 此次已检查到工作日/周末与农历转换按钮显式为 `type="button"`；表单与外部操作区是兄弟节点，未发现嵌套 form。number 默认 step=1 与整数规则一致，没有证据将 step 单独认定为本次根因。

#### 修复契约

- 空日期仅表示普通任务未安排，不得为了初始化规则而把任务本身设为今天。规则草稿可使用合法的 today fallback 初始化，但 daily/weekly 提交时剔除无关 month/monthDay；重复未设日期仍通过明确提示阻止保存。
- 用户从空日期首次选定计划日期时补齐相关规则默认月/日；只能补尚未建立或无效的默认值，不能在之后每次改日期时重置用户已选择的自定义重复规则。切换频率、历法和 selector 时规范化提交参数，只保留适用字段，并使可见默认值与实际 payload 一致。
- 星期选择应有确定语义：全部取消表示恢复默认/不额外限制时，提交 undefined 而非空数组；若某模式确实要求至少选择一天，则在同一表单内明确报错，不提交隐藏非法值。
- 提交前执行与领域规则一致的校验；服务端继续独立校验，不以放开非法 month/day 为代价掩盖前端缺陷。整数范围、required、日期/时区与重复基准约束必须一致；辅助按钮明确 button，保存按钮明确 submit。
- 表单通过原生 invalid 捕获或等价可访问校验，明确显示未满足的字段、聚焦对应控件；不能只依赖宿主 WebView 可能不明显的浏览器气泡。保存请求的失败必须在当前抽屉内显示 `role="alert"` 的本地化提示，而非只放在遮罩后背景。
- 失败不关闭抽屉、不清空用户输入；busy 状态结束后允许修正重试。只有服务明确保存成功才关闭。需要区分“HTML 尚未发出请求”“业务校验拒绝”“实际请求失败”，不伪装成保存成功或无限等待。

#### 验证要求

覆盖原生无日期普通待办→补日期→开启每日/每周/每月重复→保存的完整入口，并检查请求中的隐藏字段；含有效日期普通任务及已经自定义规则的任务作对照。频率/历法切换、空星期、空/非整数输入、无效月份及模板附件拒绝均要在抽屉内给出反馈。浏览器验证需证明 invalid 不会静默吞提交、辅助按钮不误提交；服务契约验证需证明正常配置重复仍保留原笔记 ID/正文且不创建辅助笔记。

以上是根据代码与用户场景确定的修复设计，不代表当前实现或真实 Joplin 保存已经通过；具体结果见测试记录。

## 12. 启动、迁移与删除恢复

### 12.1 启动顺序

注册设置与能力检查 → ready 面板/加载态 → 分页发现数据本/控制笔记 → 读取并校验操作 → 导入本机未完成 outbox → 归并与冲突识别 → 读取实际待办 → 原生变化对照 → 恢复允许的投影 → 发布查询快照。

数据尚未解密/模板未同步时保留加载或受限状态，不显示空白成功。同步完成后再次执行幂等增量流程，不反复注册事件监听器或定时器。

### 12.2 schema 迁移

升级先识别 schema 与备份相关控制/模板内容，追加迁移标记并保留旧操作，不能原地全量覆盖日志。未知新 schema 只读。多设备运行不同版本时，不允许旧版本“修复”它不懂的字段。数据库/笔记 ID 不因版本升级重新生成。

本地缓存丢失可由同步资料重建；日志归档/压缩需要明确水位与恢复证明，本版不自动删除历史操作。操作规模达到阈值提供诊断与备份建议，不能让用户因无提示压缩失去跨端晚到操作。

### 12.3 删除与停用

删除入口展示“只停止重复 / 删除当前任务 / 删除系列并保留历史 / 明确删除历史”的范围；正文与附件物理删除交由原生笔记机制，插件不直接删除共享资源。停止系列清未来提醒、保留操作和模板引用；停用插件后原生笔记仍可访问。

插件重新启用时先读原生变更，再重建投影，不能用陈旧缓存把已删除/脱管任务恢复为待办。数据控制笔记被删除属于恢复事件：显示缺失及可用关联笔记，不静默建立同名新系列。用户明确恢复才能从备份/已保留模板重建，并保留原系列身份或显式建立新系列。

## 13. 模块接口约束与编码规则

| 接口 | 责任 |
| --- | --- |
| `TaskRepository` | 分页待办、按 ID 获取、最小字段投影、事件游标；隔离宿主字段 |
| `SeriesStore` | userData 独立操作写入/读回、键枚举兼容、模板引用；不提供伪事务方法 |
| `LocalIntentStore` | 设备 ID、outbox 分片、阶段恢复、本机偏好 |
| `SeriesReducer` | 操作集合与 DAG → 状态/冲突/待恢复动作；纯函数 |
| `RecurrenceEngine` | 原始锚点 → 候选日期、结束检查、可见区间预计项 |
| `TimeZonePort` / `LunarCalendarPort` | 显式输入 zone/日期、边界校验、版本诊断 |
| `ProjectionPlanner` | 状态 + 原生快照 → 最小写集及 expected before/after |
| `ProjectionExecutor` | 阶段保存、读回、错误分类与恢复；不负责悄悄改业务规则 |
| `PanelBridge` | ready、请求去重、快照版本、校验消息与错误 |

采用严格 TS、显式 discriminated union 与错误类型；关键日期不能用裸 number 混传。日志必须包含操作/系列/周期 ID、阶段与错误码，但默认不记录完整正文、附件路径或敏感标题。每次结构变更同步维护代码结构文档，实际测试结论由测试工程师记录。

## 14. 典型故障恢复表

| 故障点 | 重启/归并后处理 |
| --- | --- |
| 操作写入前崩溃 | outbox 重写同 opId，未保存则不显示成功 |
| 完成已保存、Advance 未保存 | 归并后针对活动未消费周期补一个消费依据明确的 Advance |

| 绑定已存、提醒写失败 | 保留任务并显示提醒未排入，恢复最小字段投影 |

| 两端已创建不同后继 | 同逻辑周期候选归并；未编辑候选收敛，编辑分支保留并暂停 |
| 控制笔记到达而模板未到 | 等待同步，不以空正文生成任务 |
| 用户删除当前/转换普通笔记 | 暂停/脱管，不补建；恢复必须明确操作 |
| userData 损坏/未知 schema | 原数据保留、只读诊断，不按空对象重建 |
| 规则冲突且一端已推进 | 已生成内容保留，不静默回写；暂停新的推进，解决分支后决定当前有效计划 |

## 16. 明确风险与设计未证明部分

1. **无事务、无 CAS：** 本机读取检查与实际保存之间有竞争窗口；不可保证任何时刻物理笔记从不重复或原生字段完全不被并发覆盖。
2. **最终同步条件：** 设备离线、数据未上传、加密未解开、控制笔记被删除时不能自动收敛；用户编辑的分支需要保留并可能人工选择。
3. **已投递通知：** 多端抢先投递或旧提醒已触发不能撤销；只能取消尚未触发的后续投影，不能承诺通知全设备 exactly-once。
4. **userData 枚举布局：** 当前依赖公开字段内的源码布局，需兼容门槛和只读失败策略；不能假称有列键公开 API。
5. **首篇生命周期：** 当前不新建辅助数据笔记；首篇自身承载系列日志与模板，误删后不能从后继关联恢复完整数据。原生删除不能被插件可靠拦截，提示与“已完成、等待生成”恢复必须明确。
6. **日志与模板增长：** 不可变资料集中在首篇 userData 仍有存储与扫描成本；减少辅助笔记不等于日志消失。安全压缩需要跨端水位或显式恢复策略，本设计不伪造该能力。
7. **时区数据库差异：** 不同宿主 Intl 数据可能不同；已确认事件不静默漂移，远期预计变化有诊断资料。
8. **农历远期分歧：** 支持范围与独立历表仍需验证，尤其临界午夜与首尾年份；不在验证前承诺全范围无误。
9. **Android 宿主生命周期：** 面板关闭/后台挂起/强停可能影响插件执行；原生通知已有能力不能替代真机测试。

上述风险是技术设计透明度要求，不代表已降低需求或取得用户对所有限制的豁免。若验证后仍无法满足关键验收，项目经理在讨论记录中提交具体影响与选项。

## 0.3.0 清理与提示实现补充

清理通过公开userDataDelete逐键删除本命名空间；preview持有5分钟token、目标指纹和确认短语，execute重核内容。普通任务可保留解除管理，或明确永久删除预览所列管理任务；原生未接管任务和他插件元数据不删除。旧数据笔记本仅在插件标记且确认空时删除，绝不递归清除其子笔记。仅在正文引用提示marker不构成所有权。

先落本机cleanup恢复记录，再清outbox并执行。中断时停止业务恢复/写入；重新预览恢复原选项和目标，仍需用户确认。成功后重置本机偏好/设备身份并解除锁，正常刷新不自动接管原生待办。预览或错误确认不执行journal重放。该操作不是全库SQL清空，不保证物理擦除宿主历史/备份/同步墓碑，也不能远程清其他设备本机记录，卸载包仍通过宿主。

首篇提示使用成对marker与引用段落；去除时识别完整段且排除代码示例，不吞提示之后用户追加正文。清理与模板提取共用纯函数，避免两套匹配语义。

## 0.3.1 清理宿主契约纠错

用户截图确认0.3.0清理停在pending。原实现stableHash(列表row)与stableHash(单篇model)整对象比较，未考虑单篇模型附加type_：GET单项经BaseModel.load/modelSelectOne/addModelMd，分页走paginatedFeed SQL字段。改为明确内容字段+规范化userData业务值的语义快照，不比较transport附加字段、updated_time或entry.t；正文/状态/v/d改变仍受保护。

删除确认改为重新GET原生user_data并确认键不存在或d为真，不依赖userDataGet空值穿过IPC后一定保持undefined。null回归是兼容边界模拟，不宣称已证实宿主固定返回null。

清理在逐笔记删除键后再次确认内容、外插件数据与本namespace无新活动键，防止清理期间编辑被覆盖/永久删除。catch持久记录阶段、对象和原错误，在下一预览可见。识别旧控制meta或校验过的创建op中明确关联root任务，必须进入预览列表再按模式处理。旧数据诊断只显示一条，不重复在warnings渲染。

实现补充：App将读取错误loadError与提交错误error分开，后台querySnapshot成功只清loadError，不应使当前提交失败提示消失。TaskForm在保存按钮前展示submitError，保留local验证提示；浏览器invalid事件也提供可见说明。该状态调整不改宿主写入协议。
