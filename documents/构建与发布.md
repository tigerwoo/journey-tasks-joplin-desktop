# 构建与发布维护手册

本文供项目维护者使用，构建、认证和上架步骤集中在此；README 仅介绍软件安装和使用。

## 先说明：到底要不要 npm token？

当前 `.github/workflows/release.yml` 采用 **npm Trusted Publishing（OIDC）**。不需要创建或在 GitHub Secrets 中填写 `NPM_TOKEN` / `NODE_AUTH_TOKEN`。但必须先在 npm 网站授权这个 GitHub 仓库的工作流；只有仓库文件，没有账号侧授权，自动发布仍然会失败。

| 用途 | 使用的身份 | 需要手动配置什么 |
| --- | --- | --- |
| 首次在本机注册并发布 npm 包 | `npm login` 登录的维护者账号 | npm 账号、包名权限，按提示完成验证和 2FA；不要求手工创建长期 token |
| 后续 GitHub Actions 发布 npm 包 | GitHub OIDC 短期凭证 | npm 包设置中的 Trusted Publisher；工作流已配置 `id-token: write` |
| 创建 GitHub Release 和上传安装包 | GitHub 自动提供的 `github.token` | 仓库允许运行 Actions；工作流已配置 `contents: write`，无需另建 GitHub PAT |

这里的“不需要 token”指不需要你创建、复制和保存长期 npm 发布令牌，并非没有认证。OIDC 自动完成身份交换。当前实现没有 token 备用分支；仅添加 `NPM_TOKEN` secret 不会让本工作流改用 token。

## 1. 本机构建与校验

准备 Git、Node.js 24.x 和 npm；在下载或检出的项目根目录执行：

```sh
npm ci
npm run build
npm run check
npm run verify:release
```

首次先构建，因为测试会读取 `dist/` 和 `publish/` 中的现有产物。`npm run check` 依次执行类型检查、测试、重新构建和安装包校验。

| 命令 | 用途 |
| --- | --- |
| `npm ci` | 按锁文件安装依赖 |
| `npm run typecheck` | TypeScript 检查 |
| `npm run build` | 编译并生成安装包 |
| `npm run dist` | 类型检查后构建 |
| `npm test` | 运行完整测试，需先有构建产物 |
| `npm run verify:package` | 运行安装包及编译产物启动测试 |
| `npm run verify:release` | 校验实际 npm 压缩包文件、版本、平台及安装包哈希 |

`dist/` 保存编译后的运行文件；`publish/` 保存 `.jpl`、对应 JSON 清单和构建信息。使用者只需安装 `.jpl`。两个目录均不提交到 Git；npm 的 `files` 和 `.npmignore` 单独控制发布包内容。修改源码后运行 `npm run check`，在 Joplin 中重新安装生成的 `.jpl` 并完全重启，即可试用。

## 2. 首次发布 npm 包（维护者在本机操作）

公开 GitHub 仓库：<https://github.com/tigerwoo/journey-tasks-joplin-desktop>。

先把准备发布的代码和发布配置提交并同步到该仓库，保持本机与公开版本一致。确认 npm 账号能够注册或拥有 `joplin-plugin-journey-tasks`；GitHub 用户名和 npm 用户名不要求相同。若该名称已被别人占用，需要先更改包名并继续满足 `joplin-plugin-` 前缀要求。

在项目根目录，完成上节的构建检查后执行：

```sh
npm login --registry=https://registry.npmjs.org/
npm whoami --registry=https://registry.npmjs.org/
npm publish --access public
```

按浏览器和终端提示完成登录、邮箱验证及 npm 要求的 2FA。最后一条命令会实际公开发布，运行前核对版本及包内容。项目的 `prepublishOnly` 会先构建、检查和校验发布包。

确认发布成功：

```sh
npm view joplin-plugin-journey-tasks version --registry=https://registry.npmjs.org/
```

这一步创建 npm 包，随后才能进入这个包的 Settings 配置后续发布身份。npm 的登录凭证由 npm 在本机管理，不要复制到仓库或文档。

## 3. 在 npm 网站配置可信发布者（只需首次及配置失效时操作）

登录 npmjs.com → 你的包 `joplin-plugin-journey-tasks` → Settings → Trusted publishing，添加 GitHub Actions：

| 字段 | 填写值 |
| --- | --- |
| Organization or user | `tigerwoo` |
| Repository | `journey-tasks-joplin-desktop` |
| Workflow filename | `release.yml`，只填文件名，不填 `.github/workflows/` |
| Environment | 留空；当前工作流没有 environment |
| Allowed actions | 必须允许直接 `npm publish`，只允许 staged publish 不适用于当前实现 |

保存后，GitHub 的工作流才能用 OIDC 发布。工作流使用 GitHub 托管的 `ubuntu-latest`，不使用自托管 runner；Node.js 24、npm 11 和 `id-token: write` 已在 YAML 中配置。

npm 当前要求新建可信发布配置在两天内完成首次成功发布，否则需要删除过期配置并重建。**重跑本机已经发布的相同版本只会跳过，不会完成一次新的 OIDC 发布**；请通过下一节的新版本标签，在有效期内验证自动发布。

## 4. 发布后续版本并获得最新版下载

1. 修改 `package.json`、`package-lock.json` 根版本及 `packages[""].version`、`src/manifest.json`，保持版本一致，例如都改为 `0.5.6`。
2. 执行 `npm run check` 和 `npm run verify:release`，提交修改并推送到公开 GitHub 仓库。
3. 在该提交创建并推送版本标签。以下示例将公开仓库单独命名为 `github`，不会假设或覆盖你本机的 `origin`：

```sh
# 仅在尚未配置这个 remote 时添加
git remote add github https://github.com/tigerwoo/journey-tasks-joplin-desktop.git
git push github HEAD:main
git tag v0.5.6
git push github v0.5.6
```

示例版本必须替换为三个文件中的实际版本。已有 `github` remote 时先用 `git remote -v` 核对地址，不要重复添加。推送需要你本机拥有该 GitHub 仓库的 Git 写权限，与 npm 登录无关。

工作流先构建检查并上传 GitHub Release，然后独立运行 npm 发布任务。GitHub Actions 中应看到 `build` 和 `publish-npm` 都成功；npm 失败时 GitHub 下载仍保留。Joplin 官方仓库再异步发现符合条件的 npm 包，GitHub Release 成功不等于商店收录完成。

最新版安装包固定链接：

<https://github.com/tigerwoo/journey-tasks-joplin-desktop/releases/latest/download/io.journey.tasks.97d1cd8a-5ed4-4cc9-9bf8-f0b287db6cad.jpl>

首次生成正式 GitHub Release 后可用，后续指向 GitHub 判定的最新正式 Release。自动化不会在每次普通代码推送时发布，只有版本标签触发。

## 5. 失败排查与重试

| 现象 | 核对方法 |
| --- | --- |
| npm E401 / E403 或 OIDC 失败 | 确认 npm 包所有权；可信发布者的仓库、所有者、工作流名及 direct publish 权限；检查是否过期 |
| GitHub Release 无法写入 | 确认仓库或组织策略允许 Actions 写入 contents，且当前运行来自公开目标仓库 |
| 没有触发发布任务 | 必须向公开仓库推送 `vX.Y.Z` 标签；手动 Run workflow 也需选择版本标签，选择分支会跳过 |
| 标签版本不匹配 | 同步 package、lockfile、manifest 版本，再创建正确的新标签 |
| npm 中已有版本 | 内容完全一致则跳过；内容不同必须升版本，不能覆盖或移动已发布版本标签 |
| npm 成功而 Joplin 中搜不到 | 先查 npm 发布状态、包名、keyword 和安装包清单，再检查官方收录情况；官方处理不是即时操作 |

重试：到 GitHub Actions 的 Release 工作流重跑失败任务，或 Run workflow 选择原版本标签。不要修改已发布版本的代码后移动原标签；已存在版本的完整性检查会拒绝不同内容。
